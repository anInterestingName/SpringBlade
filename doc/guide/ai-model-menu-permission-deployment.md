# 大模型配置只读菜单部署说明

适用于 [SpringBlade REQ-2026-008](../requirements/REQ-2026-008-ai-model-configuration.md)
与 [Saber REQ-2026-014](../../../Saber/doc/requirements/REQ-2026-014-ai-model-configuration-frontend.md)。
更新日期：2026-09-30。脚本已补齐，尚未执行数据库迁移、接口或浏览器验收。

## 1. 本次补齐范围

| 类型 | 编码 | 路径 / 归属 | 固定种子 ID |
| --- | --- | --- | --- |
| 父菜单 | `asset` | `/asset`，优先复用已有资产管理 | `220260909100000001` |
| 页面菜单 | `ai_provider` | `/asset/ai-provider`，父级资产管理 | `220260930200000001` |
| 查看按钮 | `ai_provider_view` | 供应商配置页面下，类型为按钮 | `220260930200000002` |
| 页面菜单 | `ai_model` | `/asset/ai-model`，父级资产管理 | `220260930200000003` |
| 查看按钮 | `ai_model_view` | 模型配置页面下，类型为按钮 | `220260930200000004` |

- `ai:model:provider:view` 关联供应商页面菜单，`ai:model:config:view` 关联模型页面菜单。
  **Scope 的 `menu_id` 指向 `category=1` 的页面，不是 `category=2` 的查看按钮**；现有接口授权树按页面组装父节点。
- 默认只给平台种子超管角色（`tenant_id=000000`、`role_alias=administrator`，必须唯一且有效）
  补齐上述五项菜单授权与两项查看 API 授权。普通用户和租户管理员不自动获得权限。
- 不创建写操作按钮、不授予 create/edit/delete API，也不绑定或授予 `ai:model:runtime:read`。
  不撤销环境已有的其他权限，也不改动模型或供应商业务数据。
- 如果当前平台只有一个启用的顶部菜单，补齐资产管理及两个页面的三条关联；没有顶部菜单时无需关联。
  多个顶部菜单不猜测目标，由管理员在“系统管理 > 顶部菜单”的菜单配置中显式选择。

## 2. 选择部署路径

### 2.1 已有数据库：只执行增量菜单脚本

前置条件：业务建表、字典升级及后端服务已部署；确认环境采用 MySQL 8.4+、基础菜单/角色/Scope 表为 InnoDB。
先备份 `blade_menu`、`blade_scope_api`、`blade_role_menu`、`blade_role_scope`、`blade_top_menu_setting`
中涉及本功能的记录及其原始字段，保存实际角色和菜单 ID。禁止在证据中记录业务凭据。

在停用并发菜单、角色、Scope 配置修改的维护窗口内，使用同一数据库连接完整执行
[增量菜单脚本](../sql/blade/blade.mysql.upgrade.5.0.1.ai-model-menu-permission.sql)。
该脚本使用连接级变量和临时表，不支持逐段换连接或并发执行。客户端遇到 SQL 错误必须停止，禁止使用忽略错误模式。
若事务内出现错误，立即在同一连接执行 `ROLLBACK`，不要继续后续 `COMMIT`；排除原因后重新执行整个脚本。

**不要对已有数据库执行全量初始化脚本，它包含 `DROP TABLE`。**
业务表已经存在时，也不要重复执行原单次建表升级脚本来修复菜单。

### 2.2 全新数据库

[全量初始化脚本](../sql/blade/blade.mysql.all.create.sql)已同步四条新菜单/按钮、两条查看 Scope 页面关联，
以及既有种子超管的菜单和 API 授权。只可在明确允许初始化的空库使用，保留原有部署流程。
之后如创建顶部菜单，仍需在顶部菜单配置中勾选资产管理及两个页面。

## 3. 增量结果与失败处理

执行前检查结果与末尾结果均必须为 `ready=1`。`ready=0` 表示前置条件冲突，本脚本所有持久表写入均被跳过，
**不能以 SQL 客户端显示执行成功代替迁移成功**。此时按结果排查：

| 结果 | 处理 |
| --- | --- |
| `administrator_role_id` 为空 | 确认平台种子超管角色不存在、已删除或重复；不随意授权其他角色，不擅自恢复已删除角色 |
| `menu_conflicts > 0` | 检查菜单编码重复、类型错误、已删除记录、路由占用、种子 ID 冲突，或资产管理根路径/父级非标准 |
| `scope_conflicts > 0` | 检查查看资源重复、已删除/停用、Scope 类型或路径不匹配、ID 冲突，或已绑定其他菜单 |
| `grant_conflicts > 0` | 检查待新增授权/顶部关联种子 ID 是否被其他关系占用；不要删除占用记录来强行通过 |
| `manual_top_menu_required=1` | 在当前账号使用的顶部菜单中显式勾选资产管理、供应商配置、模型配置，保留原有勾选项 |

兼容已有同编码的有效菜单和查看 Scope：复用实际 ID，不重复创建；四条目标菜单统一名称、路由和父级，
保留已有图标及排序；已有资产管理根菜单不改名、不改图标或排序。
不自动复活已删除资源，不自动启用被停用 Scope，不覆盖已绑定其他菜单的查看资源。
固定 ID 与逻辑关系双重核验，重复串行执行不会增加菜单或授权记录。

正常结果：五条菜单/按钮每项 `administrator_grants=1`；两条查看 Scope 的 `category=1` 且
`administrator_grants=1`；只有一个平台顶部菜单时，三条页面关联均存在。
有重复授权历史数据时，汇总值大于 1，需由环境负责人核对，而不是自动清理。

## 4. 生效与最小授权

1. 确认前端已发布包含两个页面的版本，后端管理 API 及身份范围核验依赖已部署。
2. 为非默认角色，在“权限管理 > 角色管理”的菜单授权中保留原有勾选项，按需增加页面与对应查看按钮；
   在接口权限授权中保留原有授权，勾选相应查看 Scope。角色授权接口是全量重置，不可只提交本次新增项。
3. 供应商下钻需要同时具有两页查看权限；只查看模型的角色可以仅授予模型菜单、模型查看按钮及模型查看 Scope。
4. SQL 写入绕过应用缓存失效逻辑。由运维按当前部署机制处理相关系统/权限缓存，禁止对共享 Redis 执行 `FLUSHALL`。
   用户退出后重新登录，重新获取菜单及按钮权限；旧会话或缓存可能仍显示旧授权。
5. 检查 `/blade-system/menu/routes` 是否下发两个页面；按钮权限中应有对应 `_view` 编码。
   菜单存在而页面拒绝查看时检查按钮授权；接口拒绝时检查 API Scope、身份依赖和真实管理范围，不能靠隐藏按钮解决。

## 5. 验收与回滚

- 在独立测试库验证全量初始化、已部署库增量、重复执行、已有自定义 ID 复用、冲突时零写入、单/多顶部菜单。
  验证仅平台种子超管新增授权，普通/租户角色和写操作、内部运行权限未被扩大。
- 用户手工核验两页列表/详情、供应商到模型下钻、仅模型查看及无权限拒绝；检查 Network 和 Console。
  以 1440px、1024px、375px 及浅色/深色主题核验现有页面。检查结果不得冒充已执行的业务测试。
- 回滚优先撤销本次新增菜单和 API 授权，清理相关缓存并重新登录。根据执行前快照，在事务中只删除本次新增关系，
  恢复本次修改的四条目标菜单字段及两条查看 Scope 的原 `menu_id`；核对所有实际 ID 和关系双方再操作。
- 菜单授权种子范围为 `220260930300000001` 至 `220260930300000005`，查看 API 授权为
  `220260930400000001`、`220260930400000002`，顶部关联为 `220260930500000001` 至 `220260930500000003`。
  已复用的授权可能使用其他 ID；固定范围只是核对线索，不能据此自动删除执行前已存在的记录。
- 仅当快照证明记录由本次新增且无其他角色/顶部菜单/Scope 引用时，才可删除两页与两个按钮或新建的查看 Scope。
  资产管理根菜单是共享资源，默认保留。禁止删除提示词菜单、模型/供应商业务表、业务记录或全库回滚。
