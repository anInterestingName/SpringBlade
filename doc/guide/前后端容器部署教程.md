# SpringBlade 与 Saber 容器部署教程

## 1. 部署结构

```text
浏览器 → HTTPS 入口 Nginx
             ├─ /     → Saber Web
             └─ /api/ → Gateway → Nacos 注册的业务服务 → MySQL / Redis
```

服务器运行目录按服务划分。每个服务独立管理镜像版本和 Compose 配置：

```text
/opt/springblade/
├── app/
│   ├── gateway/
│   │   ├── docker-compose.yaml
│   │   └── .env
│   ├── auth/
│   │   ├── docker-compose.yaml
│   │   └── .env
│   └── system/                   # 其他业务服务采用相同结构
└── middleware/
    ├── mysql/
    │   ├── docker-compose.yaml
    │   └── .env
    ├── redis/
    ├── nacos/
    └── sentinel/

/opt/saber/
├── docker-compose.yaml          # Web、入口 Nginx、按需运行的 Certbot
├── .env
└── nginx/conf.d/saber.conf
```

实际需要的业务服务，例如 `admin`、`ai`、`log`，在 `app/` 下各建一个同样的目录。

## 2. 发布与配置

SpringBlade 的 [镜像工作流](../../.github/workflows/deploy.yml)构建并推送各服务镜像，标签为提交 SHA 的前 12 位。Saber 的镜像工作流使用版本标签或手动指定标签。两个工作流只发布镜像，服务器仍需执行 Compose 更新。

各服务的 `.env` 填写镜像标签、端口和所需配置。应用服务需使用可达的 Nacos、MySQL、Redis 地址；同一套服务的 Nacos namespace 与运行环境保持一致。对宿主机发布的端口使用 `0.0.0.0` 监听，服务器安全组负责限定入站来源；服务间连接目标填写实际可达的地址或同一 Docker 网络中的服务名。

| 端口 | 用途 | 安全组入站来源 |
| --- | --- | --- |
| 80、443 | Web 入口 | 网站访问来源 |
| 8080 | Gateway 默认宿主机端口 | 入口代理 |
| 3306、6379 | MySQL、Redis | 后端服务 |
| 8848、9848、18080 | Nacos 服务、gRPC、控制台 | 服务及管理端 |
| 8858 | Sentinel 控制台 | 管理端 |

独立的 Saber Web Compose 默认也使用宿主机 `8080`。它与 Gateway 部署在同一主机且都发布端口时，设置 `SABER_HTTP_PORT` 为其他空闲端口；使用上图的容器化入口时，Web 可只在容器网络内提供服务。

## 3. 启动中间件

准备好各目录的 `docker-compose.yaml` 和 `.env`，依次启动 MySQL、Redis、Nacos、Sentinel。Nacos 使用 MySQL 存储时，应在 MySQL 就绪后启动。

```bash
for service in mysql redis nacos sentinel; do
  (
    cd "/opt/springblade/middleware/$service"
    docker compose --env-file .env -f docker-compose.yaml config --quiet
    docker compose --env-file .env -f docker-compose.yaml pull
    docker compose --env-file .env -f docker-compose.yaml up -d --wait
  )
done
```

首次部署还需准备 Blade 业务表和 Nacos 配置。全新空库使用 `doc/sql/blade/blade.mysql.all.create.sql`；已有库按当前版本选择对应升级脚本，先备份再执行。全量脚本包含删表语句，不用于已有业务库。Nacos 创建与 `.env` 一致的 namespace，导入 `doc/nacos/blade.yaml`、`doc/nacos/blade-{profile}.yaml`、`doc/nacos/blade-authorization-server-{profile}.yaml` 和目标环境需要的配置；授权服务通过公共 `LauncherServiceImpl` 初始化 Nacos，并通过 Discovery 解析 `blade-system`。

## 4. 启动后端服务

在各服务的 `.env` 中填入已发布的镜像标签、服务端口和依赖地址。先启动所需业务服务，再启动 Gateway；部署顺序按本次变更涉及的模块调整。以下是基础服务的示例：

```bash
for service in system auth gateway; do
  (
    cd "/opt/springblade/app/$service"
    docker compose --env-file .env -f docker-compose.yaml config --quiet
    docker compose --env-file .env -f docker-compose.yaml pull
    docker compose --env-file .env -f docker-compose.yaml up -d --wait
  )
done
```

按需以同样方式启动 `admin`、`ai`、`log` 等服务。检查各服务已在 Nacos 注册，且登记的实例地址和端口可以被 Gateway 及调用方访问。

## 5. 启动前端与入口

Saber 生产镜像使用 `/api` 作为 API 基础路径。在 `/opt/saber/.env` 指定已发布的镜像标签，然后启动 Web 与入口代理：

```bash
cd /opt/saber
docker compose --env-file .env -f docker-compose.yaml config --quiet
docker compose --env-file .env -f docker-compose.yaml pull
docker compose --env-file .env -f docker-compose.yaml up -d --wait
```

入口 Nginx 将 `/` 转发到 Saber Web，将 `/api/` 转发到 Gateway，并去除 `/api/` 前缀。例如：

```nginx
location /api/ {
    proxy_pass http://gateway-address:8080/;
}

location / {
    proxy_pass http://web:80;
}
```

将 `gateway-address` 换成入口容器可访问的地址；如果入口与 Gateway 共用 Docker 网络，也可使用 Gateway 的服务名。`proxy_pass` 末尾的 `/` 使 `/api/blade-auth/...` 到达 Gateway 时成为 `/blade-auth/...`。HTTPS 证书申请、续期及完整入口 Compose 配置见 Saber 仓库的 `doc/guide/NGINX容器化HTTPS部署教程.md`。

## 6. 验证与更新

部署后依次检查各目录的 `docker compose ps`、中间件健康状态、Nacos 注册实例、Saber `/healthz`、HTTPS 页面及 `/api/` 路由。随后在目标环境验证登录、权限、租户及本次发布涉及的业务流程。

更新一个服务时，先记录旧镜像标签，修改该服务 `.env`，再在其目录执行：

```bash
docker compose --env-file .env -f docker-compose.yaml config --quiet
docker compose --env-file .env -f docker-compose.yaml pull
docker compose --env-file .env -f docker-compose.yaml up -d --wait
docker compose --env-file .env -f docker-compose.yaml ps
```

回滚时恢复旧镜像标签和对应配置，重复上述命令。涉及数据库结构或 API 契约的版本，应先核对发布顺序和回滚兼容性；数据库恢复使用升级前准备的备份方案。
