## 2. 测试范围与依据

- 测试目标：确认内置发现路由在 Nacos 配置与服务发现刷新后仍携带各服务独立 Path，不再将 system 请求转发至 auth。
- 范围内：Gateway 配置和镜像、发现路由重建、公开只读 HTTP 请求、未知路径和服务增删；数据库、业务写入与 Feign 契约不涉及。
- 验收依据：需求 `AC-001` 至 `AC-004`、`BR-001` 至 `BR-003` 和设计风险项。
- 编译、静态检查与真实 HTTP 验收分别记录，不能互相替代。

## 4. 测试用例

### TC-001 配置产物与编译

- 优先级：P0；关联需求：REQ-001 / AC-001；测试层级：静态检查 / 构建。
- 目标模块与入口：`blade-gateway` 的 `application.yml`、最终 Gateway JAR。
- 依赖：JDK 21、系统 Maven 和已缓存依赖；前置条件：工作区改动范围已核对。
- 数据：显式 `spring.cloud.gateway.server.webflux.discovery.locator.predicates` 配置。
- 步骤：执行 `mvn clean compile -DskipTests -pl blade-gateway -am`；使用 YAML 解析器核对 Path 谓词结构，检查 `target/classes/application.yml` 包含相同表达式。
- 可观察预期：编译成功；谓词表达式与自动配置默认的 `/{serviceId}/**` 语义一致；无 API、Feign 或 SQL 变化。HTTP 状态与业务码不适用；无业务数据副作用。
- 证据：2026-09-28 JDK 21 编译摘要 `BUILD SUCCESS`；SnakeYAML 2.6 解析结果 `name=Path, pattern='/' + serviceId + '/**'`；编译资源中的同一配置。清理：不涉及业务数据，临时解析程序已删除。
- 实际结果：编译、YAML 解析和资源检查均符合预期；状态：通过。

### TC-002 配置与发现刷新后保留 Path

- 优先级：P0；关联需求：REQ-001 / AC-001、AC-002；测试层级：Gateway / Nacos 集成。
- 目标模块与入口：`blade-gateway` 自动发现路由，Nacos 配置刷新与约 30 秒服务发现周期。
- 依赖：Gateway 使用本次镜像；auth、system、ai 实例分别健康。
- 前置条件：记录启动前 prod 命名空间与 `blade-gateway-prod.yaml`、`blade-prod.yaml`、`blade.yaml` 的版本；仅在隔离环境触发配置刷新。
- 数据：服务 ID `blade-auth`、`blade-system`、`blade-ai`，不修改业务数据。
- 步骤：先核对部署镜像 JAR 的 `application.yml` 包含显式 Path 表达式且不含本机凭据；启动 Gateway 并记录首轮路由构建；观察初次 Nacos 配置通知；继续跨越至少三个真实刷新周期，逐轮提取各服务 `applying {pattern=...} to Path` 和路由 ID。
- 可观察预期：启动及每轮刷新都保留各自 Path；不得出现仅有 `RouteDefinition matched` 而无 Path 装配的整批发现路由。HTTP 状态、业务码和响应结构在本日志用例中不适用；无业务数据副作用。
- 证据：镜像标签、带时间戳的 Gateway 日志摘要；清理：恢复仅为本用例触发的临时配置变化，不更改共享配置的其他字段。
- 实际结果：待执行；状态：未执行。

### TC-003 多服务请求与未知路径

- 优先级：P0；关联需求：REQ-001 / AC-002、AC-003；测试层级：Gateway / HTTP 回归。
- 目标模块与入口：`GET /blade-auth/register/config`、`GET /blade-system/tenant/info`、`GET /blade-ai/v3/api-docs`、未知服务前缀。
- 依赖：TC-002 路由重建日志可观察；前置条件：三个服务正常注册，使用现有匿名只读入口。
- 数据：租户查询使用验证环境现有公开域名；不写入业务数据，不记录完整查询串。
- 步骤：交替访问 auth、system、ai 至少 100 轮并覆盖三个刷新周期；再访问不存在的服务前缀；按请求时间核对 `lb-diagnostic`、Nginx 和各后端日志。
- 可观察预期：前三种入口 HTTP 200，业务码与各自原接口一致，`R<T>` 或文档响应结构不变；system 请求只选择 `blade-system` 路由，auth 和 ai 同理。未知前缀保持 404，无业务码成功结果，任何已注册服务均不接收该路径；无数据副作用。
- 证据：按服务汇总的状态码、业务码、路由 ID、选中服务及错误服务日志缺席证据；清理：只读请求无需清理业务数据。
- 实际结果：待执行；状态：未执行。

### TC-004 服务增删与无实例失败

- 优先级：P1；关联需求：REQ-001 / AC-003、AC-004；测试层级：Gateway / Nacos 集成。
- 目标模块与入口：Nacos 注册中心中的隔离服务及 `/{serviceId}/**` 路由。
- 依赖：用户具备隔离测试命名空间操作权限；前置条件：唯一前缀 `REQ2026007_` 对应服务尚未注册，记录既有路由列表。
- 数据：本轮新建的隔离测试服务 ID 和实例；不得操作生产、共享或历史实例。
- 步骤：注册隔离服务并等待实际刷新；确认新增路由含相同服务 ID 的 Path；仅下线该测试实例并验证路由随服务列表更新；在无实例窗口请求该前缀，检查没有转发给其他服务。
- 可观察预期：新增与移除路由只影响该测试服务；下线后的下一次路由刷新完成时，该前缀返回无路由的 HTTP 404。刷新前若旧路由仍在但无可用实例，可记录 Gateway 的 HTTP 503；两个阶段都不得返回其他服务的业务成功码，其他服务路由与响应不变，无业务数据副作用。
- 证据：注册前后路由 ID/Path、状态码、错误服务日志缺席证据；清理：仅注销本用例创建的隔离服务，确认无残留实例或路由。
- 实际结果：待执行；状态：未执行。

## 5. 专项检查

- [ ] Nacos 初次配置通知和每次服务发现刷新均有各服务 Path 装配日志。
- [ ] `RequestFilter` 与发现路由不会重复裁剪服务名前缀。
- [ ] 未登录公开接口维持原访问规则；受保护接口不因路由修复而放行。
- [ ] 诊断日志不含密码、Token、密钥、连接串或完整请求体。
