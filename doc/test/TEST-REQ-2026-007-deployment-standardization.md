- 测试数据：仓库文件名及脚本路径。
- 步骤：1. 列出 `script/docker` 下所有 Compose 文件；2. 搜索脚本中的 `-f` 路径；3. 对整体 `infra`、`app`、`ingress` 和独立 `middleware` 模式逐一核对文件存在；4. 执行只读 shell 语法检查。

### TC-002 监听地址与端口规划

- 优先级：P0；关联验收标准：AC-002、AC-005。
- 测试层级、模块与入口：Compose 渲染和目标环境检查；各中间件目录、Gateway、Saber 独立 Web、入口代理。
- 依赖与前置条件：Compose v2 可用；使用仅含示例占位值的临时变量副本；不执行 `up`。
- 测试数据：示例端口 80、443、8080、18080、3306、6379、8848、9848、8858。
- 步骤：1. 分别执行 `config --quiet`；2. 检查对宿主机发布的端口默认绑定 `0.0.0.0`；3. 检查 Nacos Console 为宿主机 18080、Gateway 为 8080；4. 检查同机独立 Saber Web 使用 8080 时的冲突说明和改端口示例；5. 核对部署前安全组端口来源表。
- 可观察预期：配置解析退出码为 0；映射端口与文档一致；同机端口冲突有明确处理；`127.0.0.1` 仅留在容器内探活或本机诊断；安全组来源规则由环境负责人确认。
- 证据：脱敏的配置摘要、端口表、安全组检查记录。清理：临时变量副本由执行者精确删除，不触碰服务器正式 `.env`。
- 实际结果：未执行。状态：未执行。缺陷：无。

### TC-003 空环境首次部署

- 优先级：P0；关联验收标准：AC-001、AC-002。
- 测试层级、模块与入口：集成/部署；教程第 2 至 6 节、各服务目录、MySQL、Nacos、Gateway、Saber 和入口代理。
- 依赖与前置条件：已获独立测试环境使用许可；固定镜像已发布；安全组、DNS、证书和备份已准备；测试库确认为全新空库。
- 测试数据：独立 `blade` 测试库、测试 namespace、最小 Auth/System/Gateway 及 Saber 镜像；不写真实用户凭据到证据。
- 步骤：1. 按 `middleware/<service>` 目录准备 `.env` 并逐个执行 `config`、`up`；2. 仅对空库导入全量 Blade SQL，检查必要表；3. 在测试 namespace 导入匹配 Data ID；4. 按 `app/<service>` 启动最小后端服务，再启动 Saber 和入口；5. 检查容器状态、Nacos 注册、Saber `/healthz` 的 HTTP 200，以及 HTTPS 入口的 `/` 和 `/api/` 转发；6. 由用户执行登录、权限及租户业务验收。
- 可观察预期：基础设施健康、服务实例可达、静态站点和网关路由正常；`/api/` 前缀只在入口层移除；业务验收结果由实际执行者逐项记录，构建或探活结果不得代替。
- 证据：脱敏的镜像标签、状态、HTTP 状态码、Nacos 实例和业务验收记录。清理：仅由环境所有者停止该独立环境并清理带前缀资源；保留失败证据和必要备份。
- 实际结果：未执行。状态：未执行。缺陷：无。

### TC-004 跨主机连接目标

- 优先级：P1；关联验收标准：AC-003。
- 测试层级、模块与入口：配置审查与集成；应用环境变量、Nacos 实例、入口 `proxy_pass`。
- 依赖与前置条件：若目标部署为多主机，由运维提供已分配的可达地址和安全组来源规则；单机环境可只执行静态检查。
- 测试数据：测试环境内网 IP 或域名，不写入正式文档。
- 步骤：1. 搜索所有连接目标是否误填 `0.0.0.0`；2. 检查 Nacos、MySQL、Redis 和代理目标为可达地址；3. 检查服务注册实例地址可由 Gateway 和调用方访问；4. 记录网络及安全组验证结果。
- 可观察预期：`0.0.0.0` 只用于监听；跨主机调用成功且安全组仅放行预定来源；Docker bridge 网络名称不作为跨主机目标。
- 证据：脱敏的配置键名、连接测试结果和实例可达性记录。清理：无业务数据；仅删除本用例临时配置副本。
- 实际结果：未执行。状态：未执行。缺陷：无。
