## 2. 摘要与目标

### 2.1 摘要

现有提示词管理未区分提示词用途和发布方式，且提示词数据按租户共享，无法支持普通用户独立维护自己的提示词。本需求新增提示词类型和发布方式，并复用 SpringBlade 现有 DataScope 数据权限控制“本人可见”和“全部可见”。

本需求允许重新调整现有提示词管理的数据模型和接口，不以兼容旧接口或旧数据行为为前置条件；后续提示词相关需求必须遵守本需求确立的类型、发布方式和数据权限契约。

### 2.2 需求目标

1. 使用提示词类型区分系统、文本、图像及其他业务用途，类型表达业务用途，不表达模型消息角色。
2. 支持普通发布和自动发布两种发布方式，并明确两者的保存、校验、版本和失败语义。
3. 普通用户对本人创建的提示词拥有完整管理权限，对他人提示词不具备任何访问权限。
4. 管理员可查看和管理当前租户全部提示词；超级管理员在当前租户上下文中可查看和管理全部提示词。
5. 复用现有 `blade_scope_data`、`DataScopeEnum.OWN` 和 `DataScopeEnum.ALL`，不新增提示词专属数据权限引擎或提示词表内的数据范围字段。
6. 保证数据权限同时覆盖列表、详情、版本和全部写操作，避免只限制列表而产生按 ID 越权。

### 2.3 非目标

- 本需求不新增 `data_scope`、`owner_user_id` 等提示词专属归属字段；本人范围复用标准基础字段 `create_user` 和现有 DataScope 配置。
- 本需求不建设跨租户提示词管理；超级管理员跨租户汇总查询、切换租户和批量管理另行提出需求。
- 本需求不支持同一租户内不同用户使用相同提示词编码；提示词编码仍在当前租户内保持唯一。
- 本需求不建设提示词市场、公开分享、收藏、评分、推荐或审批流。
- 本需求不改变固定指令、用户模板和变量定义的消息组成规则。
- 本需求不建设定时发布、灰度发布、异步发布任务或自动发布失败重试队列。
- 本需求不要求兼容现有提示词管理接口的旧数据范围行为；已有调用方应按本需求的新契约调整。

## 3. 用户故事与范围

### 3.1 用户故事

| 故事编号 | 优先级 | 用户故事 | 典型场景 | 依赖 |
| --- | --- | --- | --- | --- |
| US-001 | Must | 作为普通用户，我希望创建和发布自己的提示词，以便维护个人业务提示词。 | 新建、编辑、预览和发布个人提示词 | 登录、提示词权限 |
| US-002 | Must | 作为普通用户，我希望只能看到自己的提示词，以避免查看或修改其他用户的数据。 | 打开提示词列表、详情和版本历史 | DataScope 本人可见 |
| US-003 | Must | 作为租户管理员，我希望管理当前租户全部提示词，以便统一维护租户提示词。 | 管理租户内提示词和发布版本 | DataScope 全部可见 |
| US-004 | Must | 作为提示词维护者，我希望区分提示词用途，以便不同业务能够按稳定类型使用提示词。 | 创建、查询和维护不同用途提示词 | 提示词类型 |
| US-005 | Must | 作为提示词维护者，我希望选择普通发布或自动发布，以便按风险和效率选择上线方式。 | 手工确认发布或保存即发布 | 发布方式 |

### 3.2 范围内

- 新增提示词类型字段、类型名称和类型校验。
- 首期支持系统、文本、图像和通用等用途分类；具体稳定编码在详细设计中固定。
- 新增发布方式字段，支持普通发布和自动发布。
- 普通用户本人提示词的新增、查看、编辑、复制、删除、预览、发布、停用、版本查看和回滚。
- 管理员当前租户内全部提示词的上述管理能力。
- 复用现有 DataScope 配置，对列表、详情、版本和写操作统一执行本人/全部数据范围。
- Saber 提示词页面增加类型、发布方式的展示、筛选和编辑交互。
- 同步 MySQL 全量/升级脚本、权限数据和相关文档。

### 3.3 范围外

- 普通用户查看其他用户提示词，即使已知提示词 ID、编码或版本 ID。
- 按部门、机构及子级或自定义组织树控制提示词范围；本需求只使用本人和全部两种数据范围。
- 超级管理员跨租户聚合查询和跨租户修改。
- 每条提示词独立选择本人、部门或全租户可见范围。
- 定时发布、审批发布、灰度发布和发布前多级审核。
- 自动发布的失败重试队列和异步发布任务中心。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录当前租户，且具备对应的提示词 API Scope；角色的数据权限已配置。
- 触发入口：提示词管理页面或提示词管理 API。
- 最终结果：提示词只能被数据权限允许的用户访问；普通发布保留草稿确认流程，自动发布在保存成功后立即生成当前版本。

1. 用户创建提示词并提交类型、发布方式、名称、编码和模板内容。
2. 系统从安全上下文写入租户和创建人，不信任客户端提交的租户或创建人字段。
3. 系统按当前角色的数据权限过滤可访问提示词；普通用户只返回本人数据，管理员返回当前租户全部数据。
4. 普通发布先保存草稿，再由具备发布权限的用户执行发布。
5. 自动发布在一次原子操作中完成草稿校验、版本生成和当前版本切换。
6. 查询、编辑、复制、删除、发布、停用和回滚均执行一致的数据权限校验。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([开始]) --> B{已登录且具备接口权限?}
    B -- 否 --> C[返回认证或权限失败]
    C --> Z([结束])
    B -- 是 --> D[读取当前租户和用户上下文]
    D --> E[按 DataScope 查询或校验提示词]
    E --> F{资源在数据范围内?}
    F -- 否 --> G[返回不存在或无权限且不泄露正文]
    G --> Z
    F -- 是 --> H{普通发布还是自动发布?}
    H -- 普通发布 --> I[保存草稿或执行独立发布]
    H -- 自动发布 --> J[校验并原子保存草稿和发布版本]
    I --> K{执行成功?}
    J --> K
    K -- 否 --> L[返回错误且保持原状态]
    L --> Z
    K -- 是 --> M[返回当前状态和版本信息]
    M --> Z
~~~

### 4.3 异常与替代流程

| 编号 | 触发条件 | 系统行为 | 用户提示 | 数据是否改变 |
| --- | --- | --- | --- | :---: |
| EX-001 | 未登录或没有对应 API Scope | 拒绝请求 | 未登录或无权限 | 否 |
| EX-002 | 普通用户访问其他用户提示词 | 按不存在或无权限处理，不返回正文和版本信息 | 提示词不存在或无访问权限 | 否 |
| EX-003 | 客户端提交伪造的租户 ID、创建人或发布人 | 忽略客户端归属字段，以安全上下文为准 | 参数无效或归属不允许 | 否 |
| EX-004 | 自动发布模板校验失败 | 拒绝整个自动发布操作 | 提示词内容校验失败 | 否 |
| EX-005 | 自动发布过程中版本生成或主记录切换失败 | 整体回滚，保留原线上版本 | 自动发布失败，请重试 | 否 |
| EX-006 | 提示词类型或发布方式不在启用值域 | 拒绝保存 | 类型或发布方式无效 | 否 |
| EX-007 | 数据权限配置缺失或无法确定访问范围 | 默认拒绝受保护资源访问，不扩大数据范围 | 数据权限未配置或暂不可用 | 否 |

## 5. 功能需求与验收标准

### 5.1 REQ-001 提示词类型

#### 5.1.1 需求说明

- 关联用户故事：`US-004`
- 优先级：Must
- 触发入口：提示词新增、编辑、复制、列表和详情接口。
- 前置条件：用户具备对应操作权限。
- 输入：提示词类型及现有提示词内容。
- 处理规则：
  1. 类型表示提示词业务用途，不表示 `SYSTEM`/`USER` 消息角色。
  2. 类型编码必须稳定，可供后续业务按类型筛选和使用。
  3. 类型必须写入主记录；发布版本保存当次类型快照。
  4. 类型变更只影响后续发布版本，不能修改历史版本快照。
  5. 列表支持按类型筛选，详情和版本明确返回类型编码及名称。
- 输出：列表、详情和版本信息返回类型编码及名称。
- 限制：类型只能使用系统启用的值域。

#### 5.1.2 验收标准

- `AC-001`：Given 用户提交启用的提示词类型，When 创建提示词，Then 主记录保存该类型并在详情中返回类型名称。
- `AC-002`：Given 提示词已经发布，When 修改类型并发布新版本，Then 历史发布版本的类型保持不变，新版本使用新类型。
- `AC-003`：Given 用户提交未启用的类型，When 创建或更新提示词，Then 请求被拒绝且数据不改变。
- `AC-004`：Given 当前数据范围内存在不同类型提示词，When 用户按类型筛选，Then 只返回数据范围内且类型匹配的记录。

### 5.2 REQ-002 发布方式

#### 5.2.1 需求说明

- 关联用户故事：`US-005`
- 优先级：Must
- 触发入口：提示词新增、编辑和发布操作。
- 前置条件：用户具备提示词写权限；自动发布用户还必须具备发布权限。
- 输入：普通发布或自动发布方式、提示词草稿内容。
- 处理规则：
  1. `MANUAL` 表示保存草稿和发布版本分离，保持草稿不影响线上版本。
  2. `AUTO` 表示保存操作通过发布校验后立即生成发布版本并切换当前版本。
  3. 自动发布必须在一次原子业务操作中完成；任一步失败都不能产生部分状态。
  4. 发布方式变更应受并发版本校验保护，陈旧客户端不能覆盖最新配置。
  5. 发布版本必须能区分普通发布、自动发布和回滚来源。
- 输出：返回草稿状态、发布状态、当前版本和发布方式。
- 限制：自动发布不创建可被误认为已上线的半成品草稿。

#### 5.2.2 验收标准

- `AC-005`：Given 提示词发布方式为 `MANUAL`，When 用户保存内容，Then 只更新草稿，当前线上版本保持不变。
- `AC-006`：Given 提示词发布方式为 `AUTO` 且发布校验通过，When 用户保存内容，Then 系统生成新版本并将其切换为当前版本。
- `AC-007`：Given 自动发布任一步骤失败，When 操作结束，Then 草稿、当前版本和历史版本均保持操作前状态。
- `AC-008`：Given 用户不具备发布权限，When 以自动发布方式保存提示词，Then 系统拒绝且数据不改变。

### 5.3 REQ-003 基于现有 DataScope 的数据访问

#### 5.3.1 需求说明

- 关联用户故事：`US-002`、`US-003`
- 优先级：Must
- 触发入口：提示词列表、详情、版本及所有写操作。
- 前置条件：用户已登录当前租户，角色已配置提示词 API Scope 和数据权限。
- 输入：提示词查询条件、资源 ID、版本 ID 或写操作请求。
- 处理规则：
  1. 不新增提示词专属数据范围字段和特殊角色判断逻辑。
  2. 复用 `blade_scope_data`，以提示词基础字段 `create_user` 作为本人数据条件。
  3. 普通用户默认使用 `OWN` 范围；管理员和超级管理员默认使用 `ALL` 范围，但实际访问范围以角色当前绑定的 OWN/ALL 配置为准，切换为 OWN 时同样按当前用户 `create_user` 过滤。
  4. 数据权限必须覆盖列表、详情、版本、复制来源、编辑、删除、发布、停用和回滚。
  5. 版本数据的访问范围以所属提示词主记录为准，不以版本发布人作为本人条件。
  6. API Scope 负责动作权限，DataScope 负责数据范围，两者必须同时满足。
  7. 当前需求不开放跨租户提示词管理；超级管理员的全部范围限定在当前租户上下文内。
  8. 无法取得有效 DataScope 时按最小权限原则拒绝访问，不得默认放行全部数据。
- 输出：只返回当前角色数据范围内的记录或业务结果。
- 限制：不得信任客户端提交的 `tenantId`、`createUser`、`publishUser` 或其他归属字段。

#### 5.3.2 验收标准

- `AC-009`：Given 普通用户拥有提示词查看权限且当前租户存在本人和他人提示词，When 查询列表，Then 只返回本人提示词。
- `AC-010`：Given 普通用户知道他人提示词 ID，When 查询详情、版本或发起写操作，Then 系统拒绝且不泄露资源正文、版本和归属信息。
- `AC-011`：Given 租户管理员拥有全部数据权限，When 查询当前租户提示词，Then 返回当前租户全部符合条件的提示词。
- `AC-012`：Given 用户伪造其他租户或其他用户的归属字段，When 创建或更新提示词，Then 服务端仍使用安全上下文确定归属，伪造字段不生效。
- `AC-013`：Given 普通用户访问他人提示词的版本 ID，When 查询版本详情或执行回滚，Then 系统拒绝且数据不改变。

### 5.4 REQ-004 普通用户本人完整管理权限

#### 5.4.1 需求说明

- 关联用户故事：`US-001`、`US-002`
- 优先级：Must
- 触发入口：提示词管理页面和管理 API。
- 前置条件：普通用户已获得对应提示词 API Scope。
- 处理规则：
  1. 普通用户可对本人提示词执行新增、查看、编辑、复制、删除、预览、发布、停用、版本查看和回滚。
  2. 新建提示词的创建人由服务端从安全上下文写入，创建后不得由客户端修改。
  3. 复制来源必须先通过数据权限校验；普通用户不能把他人提示词复制为自己的资源。
  4. 管理员对当前租户提示词不受创建人范围限制，但仍需满足动作 API Scope。
  5. 数据权限变化后，下一次查询和写操作必须使用最新范围，不沿用客户端缓存判断。
- 输出：返回成功结果或明确的数据权限错误。
- 限制：普通用户无权管理任何他人资源。

#### 5.4.2 验收标准

- `AC-014`：Given 普通用户拥有新增、编辑和发布权限，When 创建并发布本人提示词，Then 操作成功且提示词创建人为当前用户。
- `AC-015`：Given 普通用户拥有本人提示词，When 执行编辑、停用、回滚或删除，Then 操作成功并只影响本人资源。
- `AC-016`：Given 普通用户没有他人提示词的数据权限，When 尝试复制、编辑或删除他人提示词，Then 操作失败且他人数据不改变。
- `AC-017`：Given 管理员具有全部数据范围但缺少某项动作 API Scope，When 执行该动作，Then 系统仍拒绝且数据不改变。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 提示词类型必须来自启用值域，类型用于业务用途分类，不用于消息角色判断 | 新增、编辑、发布 | 拒绝操作且数据不改变 |
| BR-002 | 提示词发布方式只能是普通发布或自动发布 | 新增、编辑、发布 | 拒绝操作且数据不改变 |
| BR-003 | 提示词编码在当前租户内唯一且创建后保持稳定 | 新增、复制、编辑 | 返回编码冲突或不可修改 |
| BR-004 | 提示词创建人由服务端写入，普通用户只能访问本人数据 | 所有管理操作 | 返回不存在或无权限 |
| BR-005 | 管理员可访问当前租户全部提示词，普通用户不得访问他人提示词 | 查询和写操作 | 拒绝操作且不泄露资源 |
| BR-006 | DataScope 负责数据范围，API Scope 负责动作权限，两者不可互相替代 | 所有管理 API | 任何一项不满足均拒绝 |
| BR-007 | 自动发布必须校验、生成版本和切换当前版本原子完成 | 自动发布 | 失败时整体回滚 |
| BR-008 | 提示词版本保存发布时的类型和发布来源快照，历史版本不可修改 | 版本历史和回滚 | 拒绝修改历史版本 |
| BR-009 | 数据权限配置缺失或异常时默认拒绝，不得扩大为全部可见 | 所有受保护查询与写操作 | 返回数据权限错误 |

### 6.2 状态与迁移

本需求不新增提示词主状态，继续使用现有草稿、已发布和已停用状态。发布方式不等同于业务状态，自动发布成功后仍进入“已发布”状态。

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| 草稿 | 尚未产生当前可用发布版本，或存在待发布草稿 | 编辑、预览、发布、受控删除 | 已发布 |
| 已发布 | 存在当前可用发布版本 | 查看、编辑草稿、发布新版本、停用、回滚 | 已发布、已停用 |
| 已停用 | 保留历史版本但禁止运行时读取 | 查看、编辑、重新发布、回滚 | 已发布 |

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 提示词主记录 | 租户内实例级 | `tenant_id`、`create_user` | 服务端租户和用户安全上下文 | `create_user` 同时作为本人数据权限字段 |
| 提示词发布版本 | 提示词实例级 | `tenant_id`、`prompt_id` | 主记录和服务端上下文 | 版本访问范围继承主提示词，不按发布人裁剪 |

SpringBlade 租户业务数据继续通过 `tenant_id` 隔离。当前需求不提供跨租户提示词管理入口；超级管理员的全部数据范围限定在当前租户上下文内。

### 7.2 当前访问规则

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 查看本人提示词 | 是 | 具备查看 API Scope，DataScope 为本人或全部 | 401/403/不存在 |
| 创建和编辑本人提示词 | 是 | 具备新增或编辑 API Scope | 401/403/业务错误 |
| 发布、停用和回滚本人提示词 | 是 | 具备对应高风险 API Scope，且资源在数据范围内 | 401/403/业务错误 |
| 管理当前租户全部提示词 | 是 | 管理员数据权限为全部，且具备动作 API Scope | 403/不存在 |

### 7.3 后续权限影响

- API Scope：复用现有 `ai:prompt:view/create/edit/copy/delete/preview/publish/disable/rollback`，并按角色授权。
- 数据权限资源：新增提示词管理 DataScope 资源，使用 `create_user` 字段配置 `OWN` 和 `ALL`。
- 作用域：提示词管理为当前租户内实例级。
- 当前处理：不新增提示词专属角色，不在业务代码中硬编码普通用户与管理员的数据过滤规则。

### 8.1 页面与操作

| 页面/入口 | 用户目标 | 主要操作 | 可见角色 | 原型链接 |
| --- | --- | --- | --- | --- |
| Saber 提示词管理 | 管理可访问提示词 | 按类型、状态和发布方式查看；新增、编辑、预览、发布、停用、回滚 | 具有提示词菜单和 API Scope 的用户 | 无 |

### 8.2 页面状态

| 状态 | 展示与行为 |
| --- | --- |
| 加载中 | 禁止重复提交，显示当前数据范围内的加载状态 |
| 空数据 | 普通用户显示本人为空；管理员显示当前租户为空，并按权限显示新增入口 |
