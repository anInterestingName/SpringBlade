## 2. 摘要与目标

### 2.1 摘要

当前项目缺少独立、统一且具有租户边界的标签分类管理能力，业务无法通过稳定的分类和标签数据形成一致的选择口径。本需求建设租户级标签分类管理 API，使当前租户内具备权限的用户能够维护分类及其标签，并向租户内业务提供统一的有效标签选项。

### 2.2 需求目标

1. 为每个租户建立相互隔离的标签分类和标签数据。
2. 支持分类的查询、新增、编辑、排序、启用、停用和受控删除。
3. 支持分类下标签的查询、新增、编辑、层级调整、排序、启用、停用和受控删除。
4. 通过稳定编码、唯一性和层级约束，保证分类与标签语义明确且结构有效。
5. 提供管理查询、标签树和有效标签选项，满足租户内统一共享使用。
6. 对所有管理操作执行登录、权限、租户归属和并发变化校验。

### 2.3 非目标

- 本期不建立标签与具体业务资源之间的关联关系。
- 本期不提供跨租户共享、跨租户查询、跨租户复制或平台公共标签库。
- 本期不提供标签导入导出、合并、别名、推荐、统计和版本历史。
- 本期不提供批量新增、批量编辑、批量删除或批量状态变更。
- 本期不建设前端页面及交互原型。
- 本期不建设审计或脱敏能力。

### 3.2 范围内

- 当前租户标签分类的分页查询和详情查询。
- 分类名称、稳定编码、选择模式、最大可选数量、排序、说明和状态管理。
- 当前租户标签的分页查询、详情查询和按分类返回标签树。
- 标签名称、稳定编码、所属分类、父标签、排序、说明和状态管理。
- 标签父子层级校验，包括同分类约束、自身约束和循环层级约束。
- 分类与标签的启用、停用及有效性联动规则。
- 分类和标签的受控逻辑删除。
- 当前租户有效标签选项查询。
- 查看、新增、编辑、状态维护和删除操作权限。
- 并发修改冲突识别和明确失败反馈。

### 3.3 范围外

- 标签与其他业务实体的绑定、解绑及引用统计。
- 分类或标签的审批、发布、回滚和历史快照。
- 分类或标签的多语言名称管理。
- 自由文本标签、用户临时标签和个人私有标签。
- 按用户、部门或岗位进一步划分标签数据可见范围。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录当前租户，并具备对应的标签分类管理权限。
- 触发入口：标签分类管理 API。
- 最终结果：分类和标签在当前租户内按稳定结构保存，并根据分类与标签状态提供有效选项。

1. 用户查询当前租户的分类列表，并选择新增、查看、编辑、状态变更或删除操作。
2. 用户进入某个分类后，查询该分类的标签列表或标签树，并维护标签内容、层级和顺序。
3. 系统校验权限、租户归属、编码唯一性、选择规则、父子层级和并发版本。
4. 校验通过后保存变化并返回最新结果；校验失败时返回明确原因且不改变数据。
5. 租户内使用方查询有效标签选项时，系统只返回启用分类下实际有效的启用标签。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([开始]) --> B[用户发起分类或标签操作]
    B --> C{已登录且具备权限?}
    C -- 否 --> D[拒绝操作且不改变数据]
    C -- 是 --> E{资源属于当前租户?}
    E -- 否 --> F[按资源不存在处理]
    E -- 是 --> G{业务规则校验通过?}
    G -- 否 --> H[返回具体校验原因]
    G -- 是 --> I[保存分类或标签变化]
    I --> J[返回当前租户最新结果]
    D --> Z([结束])
    F --> Z
    H --> Z
    J --> Z
~~~

## 5. 功能需求与验收标准

### 5.1 REQ-001 分类查询

#### 5.1.1 需求说明

- 关联用户故事：`US-001`
- 优先级：Must
- 触发入口：分类分页和详情查询 API。
- 前置条件：用户已登录当前租户并具备查看权限。
- 输入：分类名称、分类编码、状态及分页条件，或分类 ID。
- 处理规则：
  1. 查询必须限制在当前租户且排除已逻辑删除数据。
  2. 分页查询支持按名称、编码和状态筛选，并按排序值和创建时间形成稳定顺序。
  3. 列表应返回分类基本信息、状态、标签数量和更新时间。
  4. 详情应返回分类完整可维护信息和当前并发版本。
- 输出：当前租户分类分页结果或分类详情。

#### 5.1.2 验收标准

- `AC-001`：Given 当前租户存在多个分类，When 按名称、编码或状态查询，Then 仅返回当前租户内符合条件且未删除的分类。
- `AC-002`：Given 分类属于其他租户，When 当前用户按 ID 查询详情，Then 系统按不存在处理且不返回分类内容。
- `AC-003`：Given 多个分类排序值相同，When 查询分类列表，Then 返回顺序稳定且重复查询结果一致。

### 5.2 REQ-002 分类新增与编辑

#### 5.2.1 需求说明

- 关联用户故事：`US-002`
- 优先级：Must
- 触发入口：分类新增和编辑 API。
- 前置条件：用户已登录当前租户并具备对应新增或编辑权限。
- 输入：分类名称、分类编码、选择模式、最大可选数量、排序和说明；编辑时同时提交分类 ID 和并发版本。
- 处理规则：
  1. 分类名称和分类编码必填，去除首尾无意义空白后不得为空。
  2. 分类编码在当前租户内唯一，并符合统一的稳定编码格式。
  3. 分类编码创建后不可修改。
  4. 选择模式支持单选和多选；单选的最大可选数量固定为 1，多选的最大可选数量必须为正整数。
  5. 新增分类默认启用。
  6. 编辑必须匹配当前并发版本，禁止陈旧请求覆盖最新数据。
- 输出：新增或编辑后的分类标识、状态和最新并发版本。

#### 5.2.2 验收标准

- `AC-004`：Given 当前租户内分类编码未使用，When 提交合法分类信息，Then 系统创建启用状态的分类并返回其标识。
- `AC-005`：Given 当前租户已存在相同分类编码，When 再次创建，Then 系统拒绝且原数据不改变。
- `AC-006`：Given 分类已经创建，When 请求修改分类编码，Then 系统拒绝且分类编码保持不变。
- `AC-007`：Given 选择模式为单选，When 提交大于 1 的最大可选数量，Then 系统拒绝并返回选择规则错误。
- `AC-008`：Given 编辑请求使用陈旧并发版本，When 提交修改，Then 系统拒绝覆盖并提示刷新。

### 5.3 REQ-003 分类状态管理

#### 5.3.1 需求说明

- 关联用户故事：`US-005`
- 优先级：Must
- 触发入口：分类状态变更 API。
- 前置条件：分类属于当前租户，用户具备状态维护权限。
- 输入：分类 ID、目标状态和并发版本。
- 处理规则：
  1. 分类状态支持启用和停用。
  2. 停用分类不改变其下标签各自保存的状态。
  3. 停用分类后，该分类下所有标签均不作为有效标签选项返回。
  4. 分类重新启用后，分类下原本处于启用状态的标签恢复为有效选项。
  5. 重复提交当前状态不得产生额外数据变化。
- 输出：分类最新状态和并发版本。

#### 5.3.2 验收标准

- `AC-009`：Given 分类和其下标签均启用，When 停用分类，Then 分类下标签不再出现在有效标签选项中，标签自身状态保持不变。
- `AC-010`：Given 分类已停用且部分标签自身启用，When 重新启用分类，Then 这些启用标签重新出现在有效标签选项中。
- `AC-011`：Given 分类当前已处于目标状态，When 重复提交相同状态，Then 系统返回当前状态且不产生额外变化。

### 5.4 REQ-004 分类删除

#### 5.4.1 需求说明

- 关联用户故事：`US-006`
- 优先级：Must
- 触发入口：分类删除 API。
- 前置条件：分类属于当前租户，用户具备删除权限。
- 输入：分类 ID 和并发版本。
- 处理规则：
  1. 仅没有任何未删除标签的分类允许删除。
  2. 删除采用逻辑删除，不物理移除业务记录。
  3. 已使用过的分类编码不得因逻辑删除而在当前租户重新创建。
  4. 删除失败不得影响分类或标签数据。
- 输出：删除成功标识或明确的禁止删除原因。

#### 5.4.2 验收标准

- `AC-012`：Given 分类下不存在未删除标签，When 删除分类，Then 分类被逻辑删除且不再出现在查询结果中。
- `AC-013`：Given 分类下仍存在标签，When 删除分类，Then 系统拒绝并提示先处理分类下标签。
- `AC-014`：Given 分类已经逻辑删除，When 使用相同编码重新创建分类，Then 系统拒绝编码复用。

### 5.5 REQ-005 标签查询

#### 5.5.1 需求说明

- 关联用户故事：`US-001`、`US-007`
- 优先级：Must
- 触发入口：标签分页、详情、标签树和有效选项查询 API。
- 前置条件：用户已登录当前租户并具备查看权限。
- 输入：分类 ID、父标签 ID、标签名称、标签编码、状态、分页条件或标签 ID。
- 处理规则：
  1. 所有查询必须限制在当前租户且排除已逻辑删除数据。
  2. 分页查询支持按分类、父标签、名称、编码和状态筛选。
  3. 标签树按指定分类返回完整父子结构，供管理场景查看启用和停用标签。
  4. 有效标签选项只返回启用分类下路径有效的启用标签。
  5. 有效标签选项至少返回标签 ID、编码、名称和父标签 ID。
- 输出：标签分页、标签详情、分类标签树或有效标签选项。

#### 5.5.2 验收标准

- `AC-015`：Given 当前租户某分类存在多级标签，When 查询标签树，Then 系统返回父子关系正确且排序稳定的完整结构。
- `AC-016`：Given 标签属于其他租户，When 当前用户查询列表、详情或标签树，Then 系统不返回该标签及其内容。
- `AC-017`：Given 分类已停用，When 查询该分类的有效标签选项，Then 系统返回空列表。
- `AC-018`：Given 分类启用但某标签或其任一上级标签停用，When 查询有效标签选项，Then 该标签不作为有效选项返回。

### 5.6 REQ-006 标签新增与编辑

#### 5.6.1 需求说明

- 关联用户故事：`US-003`、`US-004`
- 优先级：Must
- 触发入口：标签新增和编辑 API。
- 前置条件：用户已登录当前租户并具备对应新增或编辑权限。
- 输入：所属分类、父标签、标签名称、标签编码、排序和说明；编辑时同时提交标签 ID 和并发版本。
- 处理规则：
  1. 标签名称、标签编码和所属分类必填。
  2. 标签编码在当前租户的所属分类内唯一，并符合统一的稳定编码格式。
  3. 标签编码和所属分类创建后不可修改。
  4. 新增标签默认启用。
  5. 父标签为空时创建根标签；父标签不为空时必须属于当前租户和同一分类。
  6. 编辑允许调整父标签，但不得选择自身或自身任一后代作为父标签。
  7. 编辑必须匹配当前并发版本。
- 输出：新增或编辑后的标签标识、状态和最新并发版本。

#### 5.6.2 验收标准

- `AC-019`：Given 当前分类内标签编码未使用，When 提交合法标签信息，Then 系统创建启用状态的标签并保持正确分类归属。
- `AC-020`：Given 当前分类已存在相同标签编码，When 再次创建，Then 系统拒绝且原标签不改变。
- `AC-021`：Given 另一分类存在相同标签编码，When 在当前分类创建该编码，Then 系统允许创建且两个标签归属明确。
- `AC-022`：Given 父标签属于其他租户或其他分类，When 创建或编辑标签，Then 系统拒绝且不改变标签结构。
- `AC-023`：Given 用户将标签自身或其后代设为父标签，When 提交编辑，Then 系统拒绝并保持原层级。
- `AC-024`：Given 标签已经创建，When 请求修改标签编码或所属分类，Then 系统拒绝且不可变字段保持不变。

### 5.7 REQ-007 标签状态管理

#### 5.7.1 需求说明

- 关联用户故事：`US-005`
- 优先级：Must
- 触发入口：标签状态变更 API。
- 前置条件：标签属于当前租户，用户具备状态维护权限。
- 输入：标签 ID、目标状态和并发版本。
- 处理规则：
  1. 标签状态支持启用和停用。
  2. 停用标签不自动改变其子标签保存的状态。
  3. 一个标签只有在所属分类、其全部上级标签和自身均启用时才属于有效标签。
  4. 重新启用父标签后，路径上全部节点均启用的子标签恢复有效。
  5. 重复提交当前状态不得产生额外数据变化。
- 输出：标签最新状态和并发版本。

#### 5.7.2 验收标准

- `AC-025`：Given 父标签和子标签均启用，When 停用父标签，Then 父标签及其子树均不作为有效选项返回，子标签自身状态保持不变。
- `AC-026`：Given 父标签停用而子标签自身启用，When 重新启用父标签且路径上无其他停用节点，Then 子标签恢复为有效选项。
- `AC-027`：Given 标签当前已处于目标状态，When 重复提交相同状态，Then 系统返回当前状态且不产生额外变化。

### 5.8 REQ-008 标签删除

#### 5.8.1 需求说明

- 关联用户故事：`US-006`
- 优先级：Must
- 触发入口：标签删除 API。
- 前置条件：标签属于当前租户，用户具备删除权限。
- 输入：标签 ID 和并发版本。
- 处理规则：
  1. 仅没有未删除子标签的叶子标签允许删除。
  2. 删除采用逻辑删除，不级联删除父标签、同级标签或其他数据。
  3. 已使用过的标签编码不得因逻辑删除而在原租户和原分类中重新创建。
  4. 删除失败不得改变标签层级和状态。
- 输出：删除成功标识或明确的禁止删除原因。

#### 5.8.2 验收标准

- `AC-028`：Given 标签没有未删除子标签，When 删除标签，Then 标签被逻辑删除且不再出现在分页、标签树和有效选项中。
- `AC-029`：Given 标签仍存在未删除子标签，When 删除标签，Then 系统拒绝且标签树保持不变。
- `AC-030`：Given 标签已经逻辑删除，When 在原分类使用相同编码重新创建，Then 系统拒绝编码复用。

### 5.9 REQ-009 权限与租户隔离

#### 5.9.1 需求说明

- 关联用户故事：`US-001` 至 `US-007`
- 优先级：Must
- 触发入口：全部标签分类管理 API。
- 前置条件：用户具有有效登录上下文和当前租户上下文。
- 处理规则：
  1. 分类和标签均归属于创建时的当前租户。
  2. 客户端不得指定或修改分类和标签的租户归属。
  3. 当前租户内分类和标签属于租户级共享数据，不按创建用户或部门进一步过滤。
  4. 查看、新增、编辑、状态维护和删除必须分别受对应权限控制。
  5. 服务端必须同时校验操作权限、当前租户和资源归属，不能只依赖调用方隐藏操作入口。
  6. 其他租户资源统一按不存在处理，不暴露资源是否存在及具体内容。
- 输出：授权范围内的业务结果，或统一认证、权限、资源不存在失败结果。

#### 5.9.2 验收标准

- `AC-031`：Given 用户未登录，When 请求任一管理接口，Then 系统拒绝访问且数据不改变。
- `AC-032`：Given 用户已登录但缺少目标操作权限，When 执行对应写操作，Then 系统拒绝且数据不改变。
- `AC-033`：Given 两个租户分别存在分类和标签，When 任一租户查询或维护数据，Then 只能访问本租户资源。
- `AC-034`：Given 同一租户内不同部门和不同创建人拥有查看权限，When 查询分类和标签，Then 返回一致的租户级共享数据。
- `AC-035`：Given 请求中尝试提交租户标识，When 创建或编辑分类、标签，Then 服务端不采用客户端提交值改变资源归属。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 分类和标签必须归属于当前安全上下文中的租户 | 全部操作 | 拒绝越租户访问或按不存在处理 |
| BR-002 | 分类编码在租户内唯一且创建后不可修改 | 分类 | 拒绝创建或修改 |
| BR-003 | 标签编码在租户和所属分类内唯一且创建后不可修改 | 标签 | 拒绝创建或修改 |
| BR-004 | 标签所属分类创建后不可修改 | 标签 | 拒绝修改 |
| BR-005 | 父标签与子标签必须属于同一租户和同一分类 | 标签层级 | 拒绝保存层级变化 |
| BR-006 | 标签不得以自身或任一后代作为父标签 | 标签层级 | 拒绝保存并保持原结构 |
| BR-007 | 单选分类最大可选数量为 1，多选分类最大可选数量为正整数 | 分类 | 拒绝非法选择规则 |
| BR-008 | 有效标签要求分类、全部上级标签和自身均启用 | 有效选项 | 不返回无效标签 |
| BR-009 | 包含标签的分类不得删除，包含子标签的标签不得删除 | 删除 | 拒绝删除且数据不改变 |
| BR-010 | 分类和标签逻辑删除后原稳定编码不得复用 | 新增 | 拒绝重复编码 |
| BR-011 | 当前租户内数据共享，不按用户和部门过滤 | 查询 | 按租户返回统一结果 |
| BR-012 | 陈旧并发版本不得覆盖最新数据 | 写操作 | 拒绝并提示刷新 |

### 6.2 状态与迁移

分类和标签分别维护启用、停用状态，状态变化不级联改写下级记录。

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| ENABLED | 数据自身启用；是否实际有效仍取决于分类和上级标签状态 | 查询、编辑、停用、受控删除 | DISABLED |
| DISABLED | 数据自身停用，不作为有效选项 | 查询、编辑、启用、受控删除 | ENABLED |

    [*] --> ENABLED: 创建成功
    ENABLED --> DISABLED: 停用
    DISABLED --> ENABLED: 启用

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 标签分类 | 租户级 | `tenant_id` | 服务端安全上下文 | 当前租户内共享，不允许客户端指定 |
| 标签 | 租户级 | `tenant_id` | 服务端安全上下文 | 必须与所属分类和父标签属于同一租户 |

本需求不提供跨租户管理入口。即使用户拥有系统级管理身份，标签分类管理也默认绑定当前租户上下文。

### 7.2 当前访问规则

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 查询分类和标签 | 是 | 具有查看权限和当前租户上下文 | 未认证或无权限时拒绝；越租户资源按不存在处理 |
| 新增分类和标签 | 是 | 具有对应新增权限，输入满足唯一性和层级规则 | 返回明确业务错误且不新增数据 |
| 编辑分类和标签 | 是 | 具有对应编辑权限，资源属于当前租户且并发版本一致 | 拒绝陈旧或越租户修改 |
| 启用或停用 | 是 | 具有状态维护权限，资源属于当前租户 | 拒绝操作且状态不改变 |
| 删除分类和标签 | 是 | 具有删除权限且不存在本需求定义的内部依赖 | 拒绝删除并返回具体原因 |
| 查询有效标签选项 | 是 | 具有查看权限和当前租户上下文 | 只返回当前租户实际有效标签 |

### 7.3 权限影响

- 权限资源：标签分类、标签。
- 权限动作：查看、新增、编辑、状态维护、删除。
- 作用域：当前租户。
- 服务端必须执行最终权限校验；菜单或调用方操作入口不作为唯一保护手段。
