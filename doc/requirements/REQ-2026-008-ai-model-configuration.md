## 2. 摘要与目标

### 2.1 摘要

由 `blade-ai` 统一管理每个租户用户自己的大模型供应商接入配置及模型配置，并向其他 SpringBlade 服务提供内部配置读取能力。平台超级管理员可管理任何租户、任何用户的数据；租户管理员可管理本租户全部用户的数据；普通用户只可管理本人数据。其他服务以后再逐个适配新契约。

### 2.2 需求目标

1. 用户可登记和维护本人所有的供应商接入配置，并在其下维护多个模型配置；管理员可在各自管理范围内代用户管理。
2. 查询和写操作均遵守三级管理范围，超级管理员不会被限制为只管理非租户数据。
3. 任务明确关联模型配置 ID，执行任务的内部服务可按此 ID 读取有效运行配置及凭据；未就绪和依赖失败均有明确结果。
4. 面向管理用户的查询结果和普通日志不暴露供应商凭据。
5. 已有图片反推流程和 `fast-staratlas-ai` 保持原有运行行为。

### 2.3 非目标

- 本期不修改 `fast-staratlas-ai` 的 YAML 档案、接口或图片反推环境配置，也不迁移其现有档案。
- 本期不实现模型推理调用、连接测试、模型自动发现、效果评测、费用统计或自动路由。
- 本期不让浏览器或普通管理接口读取凭据原值。
- 本期不建设额外的内部凭据分发安全方案；相关安全加固后续评估，不作为当前配置能力的前置条件。
- 本期不建设审计产品或脱敏处理流程；仅遵守不采集、不记录、不泄露不必要敏感信息的通用安全底线。
- 其他服务改用新配置及场景默认模型绑定不纳入本期验收。Saber 管理界面与后端能力同期交付，其页面需求、设计和验收由 Saber 仓库的独立文档承接。

| US-002 | Must | 作为平台超级管理员，我希望管理所有租户和用户的配置，以便处理跨租户配置问题。 | 跨租户查询与修改配置 | 超级管理员身份 |

### 3.2 范围内

- 供应商接入配置的创建、列表、详情、更新、启停和删除；同一用户可维护同一供应商的多个接入账号。
- 模型配置的创建、列表、详情、更新、启停和删除；一条供应商接入配置可对应多条独立的模型记录。
- 三级管理范围：超级管理员管理全部租户，租户管理员管理本租户，普通用户管理本人。
- 主流供应商预设、自定义供应商，以及模型 API 协议和能力类型的可扩展选项。
- 独立的内部运行配置读取接口，可按任务关联的模型配置 ID 返回运行凭据。
- 凭据只写或替换式管理；管理查询只显示是否已配置。
- 无效字段、重复配置、关联中删除、配置停用和并发修改的明确失败结果。
- 首期包含与上述后端契约配套的 Saber 管理界面；前端功能、交互和验收在 Saber 仓库单独编写需求与详细设计，本文不重复定义页面细节。

### 3.3 范围外

- `fast-staratlas-ai` 和其他模型调用服务的本期适配；先交付 `blade-ai` 管理 API、内部读取契约及同期 Saber 管理界面。
- 将某个模型自动设为图片反推、对话等场景的默认模型。
- 普通用户通过请求参数指定其他租户或所有人；任何操作者伪造实际创建人或修改人。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：操作者已登录且处于有效租户或平台超级管理员上下文；内部读取方具有独立授权。
- 触发入口：`blade-ai` 管理接口或内部服务读取接口。
- 最终结果：配置按归属和状态保存、查询；授权内部调用取得运行所需配置，失败时不返回凭据。

1. 用户为本人建立供应商接入配置；超级管理员或租户管理员也可为管理范围内的指定用户建立配置。
2. 操作者在该供应商下建立模型配置，选择 API 协议和文本、图像或视频能力类型。
3. 系统按操作者身份限定管理范围，管理查询仅展示凭据是否已配置。
4. 任务创建时由所属业务记录其关联的模型配置 ID；执行任务的服务按该 ID 读取配置，`blade-ai` 校验启停状态，无须依赖最终用户登录态。

    J --> Z

## 5. 功能需求与验收标准

### 5.1 REQ-001 供应商接入配置管理

- 关联用户故事：`US-001`；优先级：Must。
- 每个租户用户可拥有多条供应商接入配置。配置应能识别供应商、接入地址、凭据是否已配置及启停状态。
- 普通用户创建时配置归属本人；管理员可指定管理范围内的租户和所有人，服务端必须校验目标用户归属。配置所有人与实际创建人分别记录，不得因管理员代建而将配置误归管理员所有。
- 更新时未提交新凭据不得清除原凭据。
- 删除后的标识复用规则、唯一约束和关联模型处理在数据库设计中确定。
- `AC-001`：Given 普通用户在有效租户内登录且输入合法，When 创建供应商配置，Then 列表可查到该配置，归属为当前租户和本人。
- `AC-002`：Given 已保存凭据，When 更新其他字段但未提交新凭据，Then 原凭据仍可供授权内部读取使用，管理查询仍不回显原值。
- `AC-003`：Given 供应商仍有未删除模型，When 请求删除该供应商，Then 删除被拒绝，模型不变。
- `AC-025`：Given 新建供应商或模型配置且未指定启停状态，When 保存成功，Then 初始状态为停用，内部读取不能取得运行凭据。
- `AC-026`：Given 某租户用户的配置已逻辑删除，When 在相同租户、所有人范围内重建相同管理编码，Then 返回编码重复且已删除记录不被覆盖。

### 5.2 REQ-002 模型配置管理

- 关联用户故事：`US-001`；优先级：Must。
- 一条模型配置就是一条独立记录，归属一条供应商接入配置，租户和所有人须与该供应商一致。每条记录应识别上游模型、API 协议、文本/图像/视频主要能力类型、管理名称、必要参数及启停状态。
- `contextWindow`、可接受的 `input` 类型和 `reasoningEfforts` 映射等参数归属于各自模型。供应商的整份 `models` 列表不得作为一个 JSON 字段保存；修改一条模型不得重写同供应商的其他模型。
- 同一上游模型可建立不同用途的配置，但管理标识在约定归属范围内应唯一。
- `AC-004`：Given 用户拥有供应商配置，When 创建合法模型配置，Then 模型与供应商归属一致且可在本人列表查询。
- `AC-005`：Given 操作者无权管理目标供应商，When 创建或修改模型并引用该供应商，Then 请求被拒绝且模型数据不变。
- `AC-006`：Given 模型已停用，When 内部服务读取其运行配置，Then 返回不可用且不返回凭据。
- `AC-024`：Given 同一供应商下有模型 A 和模型 B，When 单独修改模型 A 的名称或参数，Then 仅模型 A 的记录变化，模型 B 的记录和配置不变。

### 5.3 REQ-003 三级管理范围

- 关联用户故事：`US-002`、`US-003`、`US-004`；优先级：Must。
- 平台超级管理员可查询、创建、修改、启停和删除全部租户、全部用户的供应商与模型配置，包括普通租户数据；跨租户管理只授予该平台身份，不能扩大到租户管理员。
- 租户管理员可在当前租户内执行上述全部操作；普通用户仅能操作本人所有的配置。
- 三级范围同时适用于列表、详情、关联查询和全部写操作；身份由服务端判定。平台超级管理员可查看标明租户和所有人的全局列表；跨租户写入须明确选定目标租户，服务端核对目标资源、目标用户与该租户一致。租户管理员只能选择当前租户，普通用户不得指定其他租户或他人为所有人。
- `AC-007`：Given 两个租户各有多名用户配置，When 超级管理员查询列表和详情，Then 可查看全部租户、全部用户的数据。
- `AC-008`：Given 租户管理员，When 查询同租户他人及其他租户的配置，Then 前者可见，后者不可见。
- `AC-009`：Given 普通用户，When 查询列表和他人详情，Then 列表仅含本人数据，他人详情不可见。
- `AC-010`：Given 未登录用户，When 查询任一管理入口，Then 认证失败且不返回配置数据。
- `AC-011`：Given 超级管理员明确选定目标租户，When 为该租户用户创建或修改、启停、删除其配置，Then 服务端核对目标租户、资源和用户一致后操作成功，配置仍归属指定用户；目标租户不匹配时拒绝且数据不变。
- `AC-012`：Given 租户管理员，When 管理本租户其他用户配置或尝试管理其他租户配置，Then 前者在满足业务规则时成功，后者被拒绝且数据不变。
- `AC-013`：Given 普通用户，When 尝试指定他人为配置所有人或修改他人配置，Then 请求被拒绝且数据不变。
- `AC-028`：Given 当前用户管理范围无法从用户服务核验，When 请求供应商或模型配置的列表、详情或写入入口，Then 返回明确的依赖失败结果且不读取或改变配置数据。

### 5.4 REQ-004 内部配置读取

- 关联用户故事：`US-005`；优先级：Must。
- `blade-ai` 为其他 SpringBlade 服务提供版本明确的内部读取契约，首期按模型配置 ID 精确读取。每个使用模型的任务均由所属业务明确关联模型配置；配置本身确定租户和所有人，内部读取不依赖最终用户登录态，也不按租户自动挑选某个人的配置。
- 管理查询和内部运行配置读取是不同权限边界。平台超级管理员也不能从管理接口读取凭据原值；首期仅独立授权的内部读取可返回运行所需凭据。任务执行服务使用任务已关联的模型配置 ID，不能借用普通用户登录身份代替内部调用身份；失败或降级不得返回可误用的成功数据。
- `AC-014`：Given 任务已关联可用模型配置且执行服务具有内部读取权限，When 执行服务按关联 ID 读取，Then 返回该模型、供应商、归属信息和运行凭据，普通管理接口仍不暴露凭据。
- `AC-015`：Given 任务未关联模型配置、关联的 ID 不存在或内部调用未授权，When 尝试读取运行配置，Then 明确失败、不猜测默认配置且不返回凭据。
- `AC-016`：Given `blade-ai` 不可用或超时，When 调用方触发降级，Then 得到类型安全的失败结果，不能误判为有效配置。
- `AC-027`：Given 任务已关联模型配置 ID，且该配置在任务创建后、执行前发生有效更新，When 授权服务执行时按 ID 读取，Then 使用执行时最新且仍可用的配置；配置已停用或删除时明确失败，不使用旧快照。

### 5.5 REQ-005 凭据和状态边界

- 关联用户故事：`US-001`、`US-005`；优先级：Must。
- 管理查询仅返回凭据是否已配置，不返回原值；普通日志不记录凭据、Token、连接串或完整敏感请求体。
- 已停用供应商、已停用模型和缺少必要凭据的配置不可用于内部运行读取。启停不改变归属。
- `AC-017`：Given 供应商已保存凭据，When 任意有权用户查询列表和详情，Then 响应只含是否已配置，不含凭据原值。
- `AC-018`：Given 供应商停用，When 内部读取其任一模型，Then 返回不可用且不返回凭据；重新启用后按当前配置恢复可读。
- `AC-019`：Given 保存、读取或依赖失败，When 检查普通日志和错误响应，Then 不含凭据、Token、连接串或完整敏感请求体。

### 5.6 REQ-006 协议、能力类型与供应商预设

- 关联用户故事：`US-006`；优先级：Must。
- 模型 API 协议使用可扩展字典选项，首期稳定标识为 `openai-completions`、`openai-responses`、`anthropic-messages`。字典扩展不意味着模型调用方自动支持新协议；调用适配由后续需求处理。
- 模型主要能力类型为文本、图像、视频三种，同样以字典选项维护。主要分类不预断模型可接受的全部输入模态或输出格式。
- 供应商预设也作为可维护的选项，例如 OpenAI、Anthropic、Google Gemini、Microsoft Azure OpenAI、阿里云百炼、DeepSeek、百度千帆、腾讯混元、智谱 GLM、Moonshot、火山方舟、xAI 和 Mistral。预设仅帮助录入供应商信息，不代表已接入其推理 API，也不得阻止用户自定义供应商。
- 用户自己的接入地址、凭据和模型配置与全局供应商预设分离；选择预设不能让其他用户看到其凭据。
- `AC-020`：Given 创建或修改模型，When 选择三种首期协议之一和文本、图像或视频能力类型，Then 系统按字典有效项接受并保存其稳定标识。
- `AC-021`：Given 提交不存在或已失效的协议、能力字典项，When 保存模型，Then 请求被拒绝且原配置不变。
- `AC-022`：Given 用户选择供应商预设，When 创建个人供应商接入配置，Then 预设信息可用于录入，但地址与凭据仍由该用户单独维护。
- `AC-023`：Given 用户所需供应商不在预设中，When 选择自定义供应商并提交合法信息，Then 可创建个人供应商配置。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 供应商和模型均有明确租户与所有人，模型归属与供应商一致；所有人与实际操作人分开记录 | 创建、修改、查询 | 拒绝操作 |
| BR-002 | 平台超级管理员管理全部租户；租户管理员仅管理当前租户；普通用户只管理本人。跨租户写入必须明确目标租户并与目标资源及用户一致 | 所有管理读写 | 限定结果或拒绝操作 |
| BR-003 | 管理查询不回显凭据；内部读取可按模型配置 ID 返回凭据 | 所有读取 | 非内部读取不返回敏感字段 |
| BR-004 | 供应商或模型停用后不可作为运行配置 | 内部读取 | 返回配置不可用 |
| BR-005 | 有关联模型的供应商不可直接删除 | 删除供应商 | 拒绝删除 |
| BR-006 | 同一租户、所有人和管理标识下不能重复配置；逻辑删除后编码仍被占用 | 创建 | 返回重复错误 |
| BR-007 | API 协议和能力类型均引用有效字典项；供应商预设不限制自定义 | 模型与供应商录入 | 拒绝无效选项，允许自定义供应商 |
| BR-008 | 使用模型的任务须显式关联模型配置 ID，运行时读取最新有效配置，不自动选取租户或用户默认模型，也不回退到创建任务时的旧配置 | 后续任务调用方 | 缺少关联或配置不可用时任务失败 |
| BR-009 | 每个模型是一条独立记录，供应商与模型为一对多；更新一个模型不重写模型列表 | 模型管理 | 仅更新目标模型 |
| BR-010 | 新供应商和新模型默认停用；单模型输入类型和推理档位可在各自记录中保存受校验的结构化参数 | 创建与更新 | 停用配置不能运行，参数无效则拒绝写入 |

### 6.2 状态与迁移

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| 启用 | 可被进一步校验并供内部读取 | 查询、更新、停用、按引用规则删除 | 停用 |
| 停用 | 保留配置，不提供运行凭据 | 查询、更新、启用、按引用规则删除 | 启用 |
| 已删除 | 普通查询和内部读取均不可见，管理编码保留且不可复用 | 无 | 无 |

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 供应商接入配置 | 租户内用户所有 | 租户、所有人 | 普通用户取当前身份；管理员可选择管理范围内用户 | 实际创建人另行记录，超级管理员可跨租户管理 |
| 模型配置 | 租户内用户所有 | 租户、所有人、供应商 | 已校验的供应商归属 | 归属须与供应商一致 |
| 内部运行配置 | 上述资源的受控视图 | 模型、租户、所有人 | 模型配置 ID 对应的已存资源 | 首期可含运行凭据，不进入管理查询 |

### 7.2 当前访问规则

| 操作 | 是否需要认证 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 管理列表、详情 | 是 | 属于当前角色管理范围 | 限定结果或隐藏不可见资源 |
| 创建配置 | 是 | 普通用户只能为本人创建；管理员可为范围内用户创建 | 拒绝或返回校验错误 |
| 修改、启停、删除配置 | 是 | 操作者具备目标范围权限且满足状态、引用规则 | 拒绝且不改变数据 |
| 内部运行读取 | 是 | 内部调用授权、明确的模型配置 ID、配置可用 | 明确失败且不返回凭据 |

### 7.3 权限影响

- 供应商和模型管理接口及内部运行读取分别授权；动作权限码和接口资源已在详细设计及 SQL 中登记，菜单与角色授权仍须在目标环境核对。
- Saber首阶段只读菜单与查看授权已按用户要求补齐，默认只给平台种子超管增加两页及查看按钮/接口权限，不给普通角色或浏览器身份授予写权限和内部运行读取；实际部署见[只读菜单部署说明](../guide/ai-model-menu-permission-deployment.md)。
- 超级管理员跨租户读写须确保不被租户自动过滤误限制，跨租户写入时须选定目标租户并核对目标归属；租户管理员和普通用户仍受租户隔离。
- 超级管理员对全部配置、租户管理员对本租户全部配置拥有管理权限；普通用户仅管理本人配置。内部读取权限与这三级管理权限分离。

## 8. 页面与交互要求

### 8.1 页面与操作

首期交付 Saber 管理界面，并使用本需求提供的管理 API。页面入口、表单、列表、操作反馈和权限呈现由 Saber 仓库单独的需求与详细设计规定；本文仅规定后端数据和接口行为，不在两个仓库重复维护页面规则。

### 8.2 页面状态

Saber 前端文档需覆盖加载、空数据、校验失败、无权限、冲突、提交中和提交成功等状态。本后端文档要求接口提供可区分的结果，具体页面展示与操作留在 Saber 文档中定义。
