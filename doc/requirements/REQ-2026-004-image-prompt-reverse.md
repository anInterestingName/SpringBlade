## 2. 摘要与目标

### 2.1 摘要

为租户用户提供图片提示词反推能力。用户只上传图片，系统调用 `fast-staratlas-ai` 分析画面内容，从当前租户的有效标签体系中选择标签，并返回固定 JSON、正向提示词、负向提示词和必要的自由描述，方便用户复制后继续生成图片。

本需求不是恢复图片生成时的原始提示词，而是基于图片内容生成可复用、可验证、标签受控的提示词结果。

### 2.2 需求目标

1. 用户只需上传一张图片即可发起分析，不要求用户预先填写标签或 JSON。
2. 系统只能从当前租户有效标签中选取标签，不得生成租户不存在的标签编码。
3. 标签用于稳定控制，主体、场景、物体、动作和细节通过自由描述补充，避免只依赖标签造成信息损失。
4. 返回固定版本化 JSON，包含标签、视觉分析、正向提示词、负向提示词和警告。
5. 通过 Redis 共享标签快照减少每次请求传输完整标签体系，并支持多实例部署和分布式锁。
6. 将 AI 分析规则固化为可编辑、发布、回滚和追溯的版本化提示词，使分析策略能够独立升级。

### 2.3 非目标

- 不承诺从图片像素精确恢复原始提示词、模型、LoRA、Seed、采样器或 CFG 等生成参数。
- 不要求用户提供标签、固定 JSON、来源元数据或原始提示词。
- 不在本期持久化上传图片、分析历史、提示词结果或模型响应。
- 不修改现有 `blade_ai_prompt` 提示词管理表结构；图片提示词包含负向提示词和视觉分析，不直接映射为现有固定指令/用户模板。
- 不在本期建设模型供应商管理、模型效果评分、批量图片分析或异步任务中心。
- 不让浏览器直接访问 `fast-staratlas-ai` 或持有其 API Key。

## 3. 用户故事与范围

### 3.1 用户故事

| 故事编号 | 优先级 | 用户故事 | 典型场景 | 依赖 |
| --- | --- | --- | --- | --- |
| US-001 | Must | 作为租户用户，我希望上传图片后自动分析，以便快速获得可用的生图提示词。 | 资产管理中的图片反推入口 | 用户登录、AI 分析服务 |
| US-002 | Must | 作为租户用户，我希望系统只使用当前租户已有标签，以便分析结果可以被业务统一使用。 | 返回内容类型、风格、构图、光线和色彩标签 | REQ-2026-002 |
| US-003 | Must | 作为租户用户，我希望同时看到标签和自由描述，以便结果既稳定又保留画面细节。 | 复制正向提示词或查看结构化 JSON | US-001、US-002 |
| US-004 | Must | 作为维护者，我希望标签变更后分析结果使用明确版本，以便追溯结果依据。 | 标签停用或新增后的分析请求 | Redis 标签快照 |
| US-005 | Should | 作为租户用户，我希望看到不确定项和警告，以便知道哪些内容不能被模型确认。 | 图片细节不清、标签体系未覆盖 | AI 分析结果 |

### 3.2 范围内

- 在 `blade-ai` 增加受保护的图片反推入口。
- 从 `blade-system` 获取当前租户有效标签分类和标签树快照。
- 生成规范化、不可变的标签快照并计算版本摘要。
- 使用 Redis 共享标签快照、当前版本指针和构建锁。
- 首期以 Redis 为标签快照的共享读取路径，不以各应用实例的进程内缓存承载当前快照。
- 复用现有提示词管理，以稳定编码 `image_prompt_reverse` 管理 AI 分析策略的草稿、发布版本和回滚。
- 将当前发布的分析提示词物化为 Redis 不可变运行快照，并以 `analysisPromptHash` 标识版本。
- 服务端调用 `fast-staratlas-ai` 完成视觉分析和提示词生成。
- 校验返回标签必须属于本次标签快照，并遵守分类单选、多选和最大数量规则。
- 返回固定 JSON、标签置信度、自由描述、正向提示词、负向提示词和警告。
- 通过权限码控制图片反推能力，按当前租户隔离标签体系。

### 3.3 范围外

- 标签与图片资源的持久化绑定、收藏、历史版本和回溯页面。
- 跨租户标签共享或平台公共标签库。
- 自动创建或修改标签；发现标签体系覆盖不足时只返回未匹配视觉特征。
- 将结果自动发布到提示词管理模块。
- 允许浏览器或普通调用方提交任意系统指令、分析步骤或覆盖已发布的分析提示词。
- 通过图片内嵌元数据恢复原始生图参数。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录当前租户，并具备图片反推权限；当前租户存在已发布且未停用的 `image_prompt_reverse`；`fast-staratlas-ai` 和 Redis 可用。
- 触发入口：Saber 资产管理/提示词管理页面的图片反推入口。
- 最终结果：用户获得固定 JSON 和可复制提示词；系统不保存图片和本次分析结果。

1. 用户选择一张符合格式和大小限制的图片并提交分析。
2. `blade-ai` 校验身份、租户、权限、文件格式和文件大小。
3. 系统取得当前租户有效标签快照；快照不存在时按租户分布式锁生成并写入 Redis。
4. 系统按稳定编码取得当前已发布分析提示词，并确保对应的不可变运行快照存在于 Redis。
5. 系统将图片、`taxonomyHash` 和 `analysisPromptHash` 转发给 `fast-staratlas-ai`。
6. AI 服务从 Redis 读取标签与分析提示词快照，按已发布规则分析图片并生成结果。
7. `blade-ai` 二次校验标签归属和选择数量，返回固定 JSON及两个版本标识。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([开始]) --> B[用户上传图片]
    B --> C{已登录且有图片反推权限?}
    C -- 否 --> D[返回认证或权限错误]
    D --> Z([结束])
    C -- 是 --> E{图片格式和大小合法?}
    E -- 否 --> F[返回文件校验错误]
    F --> Z
    E -- 是 --> G[读取当前租户标签快照]
    G --> H{Redis 快照命中?}
    H -- 否 --> I[加分布式锁并从标签服务构建快照]
    I --> J[写入 Redis 并取得 taxonomyHash]
    H -- 是 --> J
    J --> O{分析提示词已发布且快照存在?}
    O -- 否 --> P[构建已发布提示词运行快照]
    P --> Q[取得 analysisPromptHash]
    O -- 是 --> Q
    Q --> K[携带两个 hash 调用 fast-staratlas-ai]
    K --> L{返回 JSON 和标签合法?}
    L -- 否 --> M[返回分析失败或重试提示]
    M --> Z
    L -- 是 --> N[返回标签、分析、正向/负向提示词]
    N --> Z
~~~

## 5. 功能需求与验收标准

### 5.1 REQ-001 图片反推入口与请求校验

- 关联用户故事：`US-001`
- 优先级：Must
- 触发入口：图片反推页面提交操作。
- 前置条件：用户已登录当前租户并具备图片反推权限。
- 处理规则：
  1. 请求必须包含一张图片。
  2. 服务端校验实际文件类型，不以扩展名作为唯一依据。
  3. 单次只分析一张图片，超出大小或格式范围直接拒绝。
  4. 客户端不能指定 tenantId、标签快照内容或模型配置。
- 验收标准：
  - `AC-001`：Given 用户已登录且有权限，When 上传合法图片，Then 系统进入分析流程并返回结果或明确的依赖失败。
  - `AC-002`：Given 用户未登录或无权限，When 提交图片，Then 返回统一认证/权限失败且不调用 AI 服务。
  - `AC-003`：Given 文件为空、格式不支持或超过大小限制，When 提交分析，Then 请求被拒绝且不改变任何数据。

### 5.2 REQ-002 当前租户标签快照

- 关联用户故事：`US-002`、`US-004`
- 优先级：Must
- 触发入口：图片反推流程内部。
- 处理规则：
  1. 标签快照只包含当前租户有效分类和有效标签。
  2. 快照包含分类选择模式、最大数量、标签编码、名称、说明和父级路径。
  3. 快照按规范化内容计算 `taxonomyHash`，同一内容必须得到同一 hash。
  4. 标签快照按 hash 作为不可变版本保存，当前租户通过指针指向当前 hash。
  5. 快照构建使用租户级分布式锁，避免多个实例重复查询和写入。
  6. 标签变更提交后，后续分析必须能够使用新的快照；正在执行的请求可以继续使用已取得的快照。
- 验收标准：
  - `AC-004`：Given 当前租户有有效标签，When 首次发起分析，Then 系统生成标签快照并得到 `taxonomyHash`。
  - `AC-005`：Given 多个实例同时首次构建同一租户快照，When 并发发起分析，Then 只允许一个构建流程写入，其他请求复用结果或等待后读取。
  - `AC-006`：Given 标签被新增、停用或修改，When 下一次分析使用当前标签体系，Then 结果依据新的快照版本。

### 5.3 REQ-003 受控视觉分析与标签选择

- 关联用户故事：`US-002`、`US-003`
- 优先级：Must
- 触发入口：标签快照准备完成后的 AI 分析。
- 处理规则：
  1. AI 可以生成自由视觉描述，但标签只能从本次快照中选择。
  2. 单选分类最多返回一个标签，多选分类不得超过最大数量。
  3. 未知标签编码、停用标签、跨分类标签和超限结果必须被判为无效。
  4. 标签无法覆盖的主体、物体、动作和细节写入自由分析字段，不创建临时标签。
  5. 模型结果无法通过结构校验时最多执行一次修复；仍失败则返回明确错误。
- 验收标准：
  - `AC-007`：Given 图片分析返回的所有标签都存在于当前快照，When 处理结果，Then 返回合法标签及其置信度。
  - `AC-008`：Given 模型返回未知或停用标签，When 服务端校验，Then 拒绝该结果，不把未知标签返回给用户。
  - `AC-009`：Given 某分类配置为单选或限制最大数量，When 模型返回超限标签，Then 结果校验失败且不返回超限数据。

### 5.4 REQ-004 固定 JSON 与提示词结果

- 关联用户故事：`US-003`、`US-005`
- 优先级：Must
- 处理规则：
  1. 返回 JSON 必须包含版本号、`taxonomyHash`、视觉分析、标签、正向提示词、负向提示词和警告。
  2. 标签使用稳定的 `categoryCode` 和 `tagCode`，同时返回当前名称用于展示。
  3. 正向提示词必须结合受控标签和自由描述，不能只拼接标签名称。
  4. 无法从图片确认的模型参数不得伪造，应放入警告或未知项。
  5. 结果只作为本次响应返回，不自动写入提示词管理数据。
- 验收标准：
  - `AC-010`：Given AI 分析成功，When 返回响应，Then JSON 字段结构固定、版本明确且包含正向/负向提示词。
  - `AC-011`：Given 标签体系未覆盖某个视觉细节，When 分析图片，Then 细节可以保留在自由描述或提示词中，不生成未登记标签。
  - `AC-012`：Given 用户查看结果，When 复制正向提示词或完整 JSON，Then 内容与响应一致且不包含密钥、Token 或内部连接信息。

首期固定 JSON 结构基线：

```json
{
  "schemaVersion": "1.0",
  "taxonomyHash": "sha256:...",
  "analysis": {
    "summary": "图片整体内容摘要",
    "subject": "主体、外观、动作和关系描述",
    "scene": "环境、时间、空间和背景描述",
    "details": ["材质、服饰、物体等可观察细节"],
    "unmatchedFeatures": ["当前标签体系未覆盖但提示词需要保留的特征"],
    "uncertainFeatures": ["模型无法可靠确认的内容"]
  },
  "labels": [
    {
      "categoryCode": "lighting",
      "categoryName": "光线特征",
      "selections": [
        {
          "tagCode": "neon_light",
          "tagName": "霓虹光",
          "confidence": 0.94,
          "reason": "画面主要由彩色发光体照明"
        }
      ]
    }
  ],
  "prompt": {
    "language": "en",
    "positive": "positive prompt",
    "negative": "negative prompt",
    "segments": {
      "subject": [],
      "scene": [],
      "style": [],
      "composition": [],
      "lighting": [],
      "color": [],
      "quality": []
    }
  },
  "warnings": [
    {
      "code": "generation_parameters_unknown",
      "message": "无法从图片确认原始模型、Seed、采样器和 CFG"
    }
  ]
}
```

`labels` 中没有命中的分类允许不返回；`segments` 用于解释最终提示词的组成，不代替 `positive` 和 `negative`。详细设计可以补充字段长度和枚举，但不得改变上述字段的基本语义。

成功响应还必须包含本次使用的分析提示词版本：

```json
{
  "analysisPrompt": {
    "code": "image_prompt_reverse",
    "versionId": "220260916000000001",
    "versionNo": 3,
    "contentHash": "sha256:prompt..."
  }
}
```

`schemaVersion`、`analysisPrompt.versionNo` 和 `taxonomyHash` 是三个不同概念：Schema 版本控制响应结构，分析提示词版本控制 AI 行为，标签快照控制可选标签。普通提示词发布不得擅自修改固定 JSON 字段；字段结构变化必须升级 `schemaVersion` 并同步修改后端和前端契约。

### 5.5 REQ-005 服务依赖与错误语义

- 关联用户故事：`US-004`、`US-005`
- 优先级：Must
- 处理规则：
  1. `blade-ai` 服务端持有 fast 服务凭证，客户端不能提交或覆盖模型档案、服务地址和 API Key。
  2. Redis、标签服务和 fast 服务不可用时，返回可区分的失败结果，不降级为无标签自由生成。
  3. 普通日志只记录租户、请求标识、快照 hash、耗时和错误码，不记录图片正文和完整提示词。
- 验收标准：
  - `AC-013`：Given fast 服务超时或返回依赖失败，When 用户提交分析，Then 页面显示可重试错误，不显示成功结果。
  - `AC-014`：Given Redis 不可用且无法取得标签快照，When 用户提交分析，Then 系统拒绝分析，不使用过期或未知标签体系冒充成功。
  - `AC-015`：Given 开启普通业务日志，When 分析成功或失败，Then 日志不包含图片二进制、API Key、Token 和完整提示词正文。

### 5.6 REQ-006 版本化分析策略提示词

- 关联用户故事：`US-001`、`US-004`、`US-005`
- 优先级：Must
- 触发入口：现有提示词管理的草稿、预览、发布和回滚流程；图片反推运行时读取。
- 处理规则：
  1. AI 分析策略使用稳定编码 `image_prompt_reverse`，创建后编码不可修改。
  2. 固定指令描述角色、分析目标、处理步骤、标签约束、防编造规则、提示词生成规则和输出要求。
  3. 具体标签列表不写入分析提示词，由独立 `taxonomyHash` 快照提供，避免标签变化导致无关提示词版本。
  4. 图片反推只使用当前租户已发布且未停用的版本，不读取草稿。
  5. 发布后形成不可变版本，并将运行所需内容按 `contentHash` 写入 Redis；当前指针只在 MySQL 事务提交成功后切换。
  6. 新请求使用新的当前版本；已经取得旧版本快照的进行中请求继续完成，不在请求中途切换规则。
  7. 回滚沿用现有语义：基于历史版本生成新的发布版本，不覆盖历史记录。
  8. 每次响应返回提示词编码、版本号和内容 hash，用于质量追溯。
- 验收标准：
  - `AC-016`：Given `image_prompt_reverse` 已发布，When 用户发起图片分析，Then 系统使用当前发布版本且响应包含其版本号和内容 hash。
  - `AC-017`：Given 该提示词只有草稿、未发布或已停用，When 用户发起分析，Then 系统拒绝请求且不调用视觉模型。
  - `AC-018`：Given 管理员发布新分析提示词版本，When 发布完成后发起新请求，Then 新请求使用新版本，历史响应仍可通过旧版本号和 hash 追溯。
  - `AC-019`：Given 新版本效果异常，When 管理员回滚到历史内容，Then 系统生成新的发布版本，后续请求使用回滚内容且历史版本不被修改。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 图片反推只接受当前登录用户所属租户的请求 | 入口、标签快照 | 认证或权限失败 |
| BR-002 | 标签真实来源是当前租户有效标签，Redis 只保存快照缓存 | 标签快照 | 快照缺失时重新构建，不使用硬编码副本 |
| BR-003 | `taxonomyHash` 标识不可变标签快照内容 | 请求、结果、追溯 | hash 与内容不一致时拒绝使用 |
| BR-004 | 标签结果必须满足分类选择模式和最大数量 | AI 结果校验 | 结构校验失败 |
| BR-005 | 自由描述可以包含未被标签体系覆盖的细节 | JSON、提示词 | 不创建临时标签 |
| BR-006 | 未知模型参数不得被声称为原始事实 | 结果说明 | 放入未知项或警告 |
| BR-007 | 本需求不保存图片和分析历史 | 数据边界 | 不新增持久化记录 |
| BR-008 | 标签快照主路径直接读取 Redis，不依赖进程内缓存保持多实例一致 | 标签读取 | Redis 不可用时明确失败 |
| BR-009 | AI 分析策略必须使用 `image_prompt_reverse` 当前发布版本，草稿不得进入运行时 | 分析提示词 | 未发布或停用时拒绝分析 |
| BR-010 | 分析提示词快照和标签快照相互独立 | 版本管理 | 分别使用 `analysisPromptHash`、`taxonomyHash` |
| BR-011 | 提示词升级不得在同一 `schemaVersion` 下破坏固定 JSON 字段语义 | 输出契约 | 结构变化必须升级 Schema 并同步调用方 |

### 6.2 状态与迁移

不建立持久化任务状态。单次请求只返回成功或明确失败；异步任务、取消、恢复和历史状态作为后续需求处理。

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 图片反推请求 | 租户级 | 当前租户上下文 | SpringBlade 安全上下文 | 不落库，仅在请求期间使用 |
| 标签快照当前指针 | 租户级 | `tenant_id` | 服务端上下文 | 只能读取当前租户标签 |
| 标签快照内容 | 由租户快照 hash 标识 | hash/快照索引 | 服务端生成 | 只读版本，不接受客户端指定内容 |
| 分析策略提示词 | 租户级 | `tenant_id` + `prompt_code` | 现有提示词管理 | 运行时只读当前发布版本 |
| 分析提示词运行快照 | 由内容 hash 标识 | `analysisPromptHash` | 已发布提示词版本 | Redis 不可变内容，供 fast 读取 |

### 7.2 当前访问规则

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 发起图片反推 | 是 | 有 `ai:prompt:reverse` 权限，图片合法 | 401/403/业务错误 |
| 读取当前租户标签快照 | 是 | 由图片反推服务内部调用 | 越租户或不可用时失败 |
| 写入标签快照缓存 | 否（用户不可直接调用） | 由服务端在标签变更或缓存缺失时执行 | 返回依赖失败，不开放客户端写入 |
| 管理分析提示词 | 是 | 复用现有提示词查看、编辑、发布、停用和回滚权限 | 沿用 REQ-2026-001 错误语义 |
| 读取分析提示词运行快照 | 否（用户不可直接调用） | 图片反推内部读取当前发布版本 | 缺失、未发布或停用时失败 |

### 7.3 后续权限影响

- 权限资源：`ai:prompt:reverse`。
- 内部标签读取权限：`system:tag:runtime`，用于具备图片反推权限的服务调用链。
- 作用域：当前租户级。
- 当前不新增独立角色；由部署环境决定哪些角色拥有图片反推权限。
