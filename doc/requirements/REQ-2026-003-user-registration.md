## 2. 摘要与目标

### 2.1 摘要

当前系统仅提供管理端创建用户和第三方登录后的账号绑定能力，未向未登录用户提供完整、受控的账号密码自助注册流程。本需求在现有 Saber 登录界面中增加注册入口，使面向 C 端的普通用户能够加入已有租户，并在注册成功后返回登录界面使用新账号登录。

### 2.2 需求目标

1. 为未登录用户提供账号密码自助注册能力，并与现有 Saber 登录界面共用同一套 UI。
2. 注册用户只能加入已有租户，不允许通过注册流程创建租户；未填写租户时使用默认租户 `000000`。
3. 通过注册开关、图形验证码、输入校验、频率限制和账号唯一性约束控制公开注册风险。
4. 注册成功的用户立即成为目标租户下的启用普通用户，不获得任何管理角色或组织管理权限。
5. C 端注册用户不归属管理端部门和岗位，登录后的页面与操作范围由普通用户角色控制。
6. 注册成功后返回登录界面，不在注册接口中自动签发登录凭证。

### 2.3 非目标

- 本期不支持通过注册创建租户、组织、部门、岗位或管理员账号。
- 本期不支持邮件验证码、短信验证码、手机号注册或邮箱注册。
- 本期不建设人工审核、注册申请、审批通过、审批拒绝或审批通知流程。
- 本期不支持注册成功后自动登录。
- 本期不新增独立 C 端前端应用，继续使用 Saber 的登录页面、基础布局和动态菜单能力。
- 本期不建设新的 C 端业务首页或业务功能，普通用户登录后的可用页面由现有或后续配置的角色菜单决定。
- 本期不改造第三方登录和现有第三方账号绑定流程。
- 本期不建设找回密码、邮件绑定、手机绑定、实名验证或多因素认证能力。
- 本期不为 C 端用户创建虚拟部门，不建设用户分组、会员等级或客户组织模型。
- 本期不建设审计或脱敏能力；仅遵守不采集、不记录、不输出密码和令牌等敏感信息的通用安全底线。

## 3. 用户故事与范围

### 3.1 用户故事

| 故事编号 | 优先级 | 用户故事 | 典型场景 | 依赖 |
| --- | --- | --- | --- | --- |
| US-001 | Must | 作为未登录用户，我希望通过账号和密码注册，以便获得平台普通用户账号。 | 首次进入 Saber 登录页并选择注册 | 注册功能已开启 |
| US-002 | Must | 作为注册用户，我希望加入一个已有租户，以便在该租户的数据和权限范围内使用系统。 | 使用默认租户或填写其他租户编号 | 目标租户已存在且有效 |
| US-003 | Must | 作为平台运营人员，我希望能够关闭公开注册，以便在非开放阶段阻止新用户创建账号。 | 发布、维护或风险控制期间 | 注册开关可配置 |
| US-004 | Must | 作为租户管理员，我希望自助注册用户只能获得普通用户权限，以免匿名用户取得管理能力。 | 用户向任一已有租户注册 | 租户已配置普通用户角色 |
| US-005 | Must | 作为注册成功的用户，我希望返回登录界面并使用新账号登录，以便进入同一套 Saber UI。 | 完成注册后登录 | 账号已启用 |

### 3.2 范围内

- Saber 登录界面中的用户注册入口、登录与注册模式切换及注册表单。
- 未登录用户查询当前是否开放注册所需的最小公开配置信息。
- 全局注册开关；关闭时隐藏或禁用页面入口，并由服务端拒绝直接注册请求。
- 租户编号可选输入；未填写时使用默认租户 `000000`，填写时使用用户指定的已有租户。
- 目标租户存在、有效和未删除校验。
- 账号、密码、确认密码、可选昵称和图形验证码输入。
- 账号格式、密码规则、两次密码一致性和验证码校验。
- 注册请求频率限制和重复提交控制。
- 目标租户内账号唯一性和并发重复注册控制。
- 为新用户分配目标租户下的普通用户角色，并明确无部门、无岗位的业务语义。
- 注册成功后立即启用账号，并返回 Saber 登录界面。
- 普通用户登录后的动态菜单、接口访问和管理能力限制。
- 注册失败时提供明确、可恢复且不泄露敏感信息的错误反馈。

### 3.3 范围外

- 新租户申请、租户自助开通、租户试用和租户付费流程。
- 邮件、短信、第三方身份或人工审核验证。
- 管理员代用户注册、批量注册、邀请链接和邀请码注册。
- C 端用户部门归属、岗位归属及管理端组织树维护。
- 用户注册后的资料完善、头像上传、兴趣标签和个性化推荐。
- 普通用户角色的业务菜单建设；本需求仅要求注册角色不得包含管理权限，并能够进入已配置的普通用户页面。
- 逻辑删除账号的自助恢复和账号重新注册。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户未登录，注册功能已开启，目标租户已存在并配置可用的普通用户角色。
- 触发入口：Saber 登录界面的注册入口。
- 最终结果：系统在目标租户下创建一个启用的普通用户账号，用户返回登录界面后可使用该账号登录。

1. 用户在 Saber 登录界面选择注册。
2. 系统检查注册功能是否开启；关闭时不允许进入或提交注册。
3. 用户填写租户编号、账号、密码、确认密码、昵称和图形验证码，其中租户编号和昵称可以为空。
4. 系统将空租户编号解析为默认租户 `000000`，否则使用用户填写的租户编号。
5. 系统校验目标租户、普通用户角色、输入格式、图形验证码、注册频率和租户内账号唯一性。
6. 校验通过后，系统创建启用状态的普通用户，用户业务语义为无部门、无岗位。
7. 系统返回注册成功结果，Saber 切换至登录界面并保留可安全复用的租户编号和账号。
8. 用户输入密码完成现有登录流程，系统根据普通用户角色加载可访问页面。

## 5. 功能需求与验收标准

### 5.1 REQ-001 注册入口与功能开关

#### 5.1.1 需求说明

- 关联用户故事：`US-001`、`US-003`
- 优先级：Must
- 触发入口：Saber 登录界面和公开注册接口。
- 前置条件：用户未登录。
- 输入：系统注册开关状态。
- 处理规则：
  1. 系统必须提供可配置的全局注册开关。
  2. 注册开关关闭时，Saber 不应提供可操作的注册入口。
  3. 即使调用方绕过页面直接请求注册接口，服务端仍必须根据注册开关拒绝请求。
  4. 注册开关不得影响已有账号的正常登录。
- 输出：可用的注册入口，或注册未开放的明确结果。

#### 5.1.2 验收标准

- `AC-001`：Given 注册开关已开启且用户未登录，When 用户打开 Saber 登录页，Then 页面提供可操作的注册入口。
- `AC-002`：Given 注册开关已关闭，When 用户打开 Saber 登录页，Then 页面不提供可提交的注册入口，已有登录功能保持可用。
- `AC-003`：Given 注册开关已关闭，When 调用方直接提交注册请求，Then 服务端拒绝请求且不创建用户。

### 5.2 REQ-002 租户选择与校验

#### 5.2.1 需求说明

- 关联用户故事：`US-002`
- 优先级：Must
- 触发入口：注册表单提交。
- 前置条件：注册功能已开启。
- 输入：可选租户编号。
- 处理规则：
  1. 租户编号为空或仅包含空白时，系统使用默认租户 `000000`。
  2. 租户编号对应 `blade_tenant.tenant_id` 业务字段，不是租户表雪花主键 `id`；前后端均按字符串处理，必须保留 `000000` 等编号的前导零。
  3. 用户填写租户编号时，系统使用去除首尾空白后的完整编号，不进行数值转换或模糊匹配。
  4. 目标租户必须已经存在、处于有效状态且未删除。
  5. 注册过程不得创建、恢复、启用或修改租户。
  6. 不同租户之间的用户、角色和数据归属必须保持隔离。
- 输出：已验证的目标租户，或租户不可注册的失败结果。

#### 5.2.2 验收标准

- `AC-004`：Given 注册功能开启且默认租户 `000000` 有效，When 用户未填写租户并提交合法注册信息，Then 请求和响应中的 `tenantId` 保持字符串 `"000000"`，用户创建在 `tenant_id='000000'` 下。
- `AC-005`：Given 用户填写了另一个有效的已有租户编号，When 提交合法注册信息，Then 用户创建在该租户下而不是默认租户下。
- `AC-006`：Given 用户填写的租户不存在、已停用或已删除，When 提交注册，Then 系统拒绝且不创建租户、角色或用户。
- `AC-007`：Given 两个有效租户，When 分别注册用户，Then 两个用户的租户归属、角色归属和后续访问范围相互隔离。

### 5.3 REQ-003 账号密码与表单校验

#### 5.3.1 需求说明

- 关联用户故事：`US-001`
- 优先级：Must
- 触发入口：Saber 注册表单和注册接口。
- 前置条件：注册功能已开启。
- 输入：账号、密码、确认密码、可选昵称和图形验证码。
- 处理规则：
  1. 账号、密码、确认密码和图形验证码必填；昵称选填。
  2. 昵称为空时，系统使用账号作为初始昵称。
  3. 账号去除首尾空白后长度为 4 至 32 个字符，仅允许字母、数字、点、下划线和短横线。
  4. 账号唯一性比较不区分英文字母大小写。
  5. 密码长度为 8 至 64 个字符，至少包含字母和数字，且不得与账号完全相同。
  6. 密码和确认密码必须完全一致，密码内容不执行首尾空白裁剪。
  7. 页面校验不能替代服务端校验；服务端必须独立执行相同业务规则。
  8. 密码必须沿用现有安全传输方式，响应、页面状态、日志和错误信息不得回显密码。
- 输出：通过校验的注册信息，或对应字段的明确校验错误。

#### 5.3.2 验收标准

- `AC-008`：Given 用户填写满足规则的账号、密码和确认密码，When 提交注册，Then 表单和服务端账号密码校验通过。
- `AC-009`：Given 昵称为空，When 注册成功，Then 新用户初始昵称等于注册账号。
- `AC-010`：Given 账号包含非法字符、长度越界或去除首尾空白后为空，When 提交注册，Then 系统拒绝且不创建用户。
- `AC-011`：Given 密码长度或复杂度不符合规则、与账号完全相同或两次密码不一致，When 提交注册，Then 系统拒绝且不创建用户。
- `AC-012`：Given 注册成功或失败，When 检查接口响应、前端状态和相关日志，Then 不出现明文密码、确认密码或可用于还原密码的内容。

### 5.4 REQ-004 图形验证码与频率控制

#### 5.4.1 需求说明

- 关联用户故事：`US-001`、`US-003`
- 优先级：Must
- 触发入口：获取图形验证码和提交注册。
- 前置条件：注册功能已开启。
- 输入：验证码标识、验证码内容及请求来源信息。
- 处理规则：
  1. 首版复用现有图形验证码能力，不使用邮件或短信验证码。
  2. 验证码必须具有有效期，并在注册校验后不可再次使用。
  3. 验证码错误、过期或已使用时，用户需要获取新验证码后重试。
  4. 系统必须对注册请求实施频率限制，防止单一来源、租户或账号持续批量注册。
  5. 频率限制阈值和时间窗口由详细设计定义并支持按环境配置。
- 输出：验证码校验成功，或验证码无效、操作过于频繁的失败结果。

#### 5.4.2 验收标准

- `AC-013`：Given 有效且未使用的图形验证码，When 用户提交匹配的验证码内容，Then 验证码校验通过。
- `AC-014`：Given 验证码错误、过期或已经使用，When 用户提交注册，Then 系统拒绝且不创建用户。
- `AC-015`：Given 同一请求来源、租户或账号超过配置的注册频率，When 继续提交注册，Then 系统暂时拒绝且不创建用户。
- `AC-016`：Given 邮件和短信服务均未配置，When 用户执行首版注册，Then 图形验证码注册流程仍可完整运行。

### 5.5 REQ-005 普通用户创建与角色边界

#### 5.5.1 需求说明

- 关联用户故事：`US-004`
- 优先级：Must
- 触发入口：全部注册校验通过后的用户创建。
- 前置条件：目标租户有效，并已配置属于该租户的有效普通用户角色。
- 输入：已验证的租户、账号、密码凭据和昵称。
- 处理规则：
  1. 新用户必须归属于已验证的目标租户。
  2. 新用户必须分配目标租户下的普通用户角色，不允许使用其他租户角色。
  3. 目标租户缺少普通用户角色时必须拒绝注册，不得回退到 `admin`、`administrator` 或其他管理角色。
  4. 注册过程不得根据客户端输入决定角色、部门、岗位、账号状态或逻辑删除状态。
  5. C 端注册用户的业务语义为无部门、无岗位，不创建或挂载虚拟部门。
  6. 新用户注册成功后立即处于启用状态，不存在待审核状态。
  7. 用户创建及其必要关联必须作为一个完整业务结果；任一步骤失败时不得保留部分注册数据。
- 输出：启用的目标租户普通用户账号，或角色配置、用户创建失败结果。

#### 5.5.2 验收标准

- `AC-017`：Given 目标租户和普通用户角色均有效，When 注册校验全部通过，Then 系统创建启用的普通用户并正确保存租户和角色归属。
- `AC-018`：Given 调用方尝试提交管理角色、其他租户角色、部门、岗位或账号状态，When 执行注册，Then 服务端忽略或拒绝受控字段，最终用户不获得管理权限。
- `AC-019`：Given 目标租户没有有效普通用户角色，When 用户提交注册，Then 系统拒绝且不创建用户或角色。
- `AC-020`：Given 注册过程中用户创建或关联保存失败，When 请求结束，Then 本次注册不保留任何部分成功数据。
- `AC-021`：Given C 端用户注册成功，When 管理员查看该用户，Then 用户显示为无部门、无岗位，且管理端部门树未新增虚拟部门。

### 5.6 REQ-006 注册结果与登录回跳

#### 5.6.1 需求说明

- 关联用户故事：`US-005`
- 优先级：Must
- 触发入口：注册请求完成。
- 前置条件：用户在 Saber 注册界面提交注册。
- 输入：注册成功或失败结果。
- 处理规则：
  1. 注册成功后，Saber 必须返回现有登录界面。
  2. 返回登录界面时可以保留已确认的租户编号和账号，不得保留密码、确认密码或验证码。
  3. 注册接口不得自动创建登录态、访问令牌或刷新令牌。
  4. 注册失败时保留用户可安全复用的非敏感输入，并允许修正后重试。
- 输出：登录界面及明确成功提示，或停留在注册界面的失败提示。

#### 5.6.2 验收标准

- `AC-022`：Given 用户注册成功，When Saber 处理成功响应，Then 页面显示注册成功信息并返回登录界面。
- `AC-023`：Given 用户返回登录界面，When 检查登录表单和页面状态，Then 可保留租户编号和账号，但密码、确认密码和验证码均为空。
- `AC-024`：Given 用户注册成功，When 检查响应和客户端登录状态，Then 系统未签发访问令牌或刷新令牌，用户仍处于未登录状态。
- `AC-025`：Given 注册因可修正原因失败，When 用户修正输入后再次提交，Then 无需重新进入页面即可重试，但必须使用有效的新验证码。

### 5.7 REQ-007 账号唯一性与重复注册

#### 5.7.1 需求说明

- 关联用户故事：`US-001`、`US-002`
- 优先级：Must
- 触发入口：注册账号校验和用户创建。
- 前置条件：目标租户已确定。
- 输入：目标租户和账号。
- 处理规则：
  1. 账号必须在目标租户内唯一，唯一性比较不区分英文字母大小写。
  2. 同一账号允许分别注册到不同有效租户。
  3. 已逻辑删除账号的原账号不得通过自助注册重新使用。
  4. 重复提交或并发提交同一租户和账号时，最多创建一个用户。
  5. 账号唯一性必须由持久化约束和业务校验共同保证，不能只依赖页面检查。
- 输出：账号可用并继续创建，或账号已被使用的失败结果。

#### 5.7.2 验收标准

- `AC-026`：Given 目标租户内账号不存在，When 提交合法注册，Then 系统允许创建该账号。
- `AC-027`：Given 目标租户内存在相同账号或仅大小写不同的账号，When 再次注册，Then 系统拒绝且不新增用户。
- `AC-028`：Given 另一租户存在相同账号，When 在当前目标租户注册，Then 系统允许创建且两个用户租户归属明确。
- `AC-029`：Given 原账号已经逻辑删除，When 在同一租户再次注册该账号，Then 系统拒绝账号复用。
- `AC-030`：Given 两个并发请求注册同一租户和账号，When 请求同时到达，Then 最多一个请求成功且数据库中只有一个对应账号。

### 5.8 REQ-008 Saber 共用 UI 与登录权限

#### 5.8.1 需求说明

- 关联用户故事：`US-004`、`US-005`
- 优先级：Must
- 触发入口：注册用户完成现有账号密码登录。
- 前置条件：注册用户账号启用，普通用户角色有效。
- 输入：租户、账号和密码。
- 处理规则：
  1. C 端普通用户与管理用户共用 Saber 登录页、基础布局和认证入口。
  2. 登录成功后的菜单、路由、按钮和接口访问范围必须由用户角色和现有权限体系决定。
  3. 普通用户不得因为共用 Saber UI 而看到或调用用户、角色、租户、菜单、部门、岗位等管理功能。
  4. 无部门、无岗位不得阻止普通用户登录，也不得使其自动获得全租户或管理端数据权限。
  5. 已停用或已删除用户不得登录。
- 输出：普通用户可访问的 Saber 页面，或登录、权限拒绝结果。

#### 5.8.2 验收标准

- `AC-031`：Given 启用的注册用户使用正确租户、账号和密码，When 登录 Saber，Then 登录成功并按普通用户角色加载可访问页面。
- `AC-032`：Given 普通用户已经登录，When 尝试访问管理菜单、按钮或接口，Then 系统不展示无权限入口且服务端拒绝直接请求。
- `AC-033`：Given 注册用户无部门、无岗位，When 完成登录和普通页面访问，Then 登录链路正常且不会获得额外数据范围。
- `AC-034`：Given 用户已停用或已删除，When 使用正确账号密码登录，Then 系统拒绝登录且不签发令牌。

| BR-005 | 密码必须满足首版长度和复杂度要求并与确认密码一致 | 注册表单 | 拒绝注册并提示修正 |

| BR-010 | 注册成功后返回登录页，不自动签发令牌 | 页面和认证 | 保持未登录状态 |

| DELETED | 已逻辑删除，不允许登录且账号不可自助复用 | 按现有管理流程处理 | 不适用 |

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 注册用户 | 租户级 | `tenant_id` | 用户选择或默认值，经服务端验证 | 只能归属已有有效租户 |
| 普通用户角色 | 租户级 | 角色租户归属 | 服务端按目标租户确定 | 不接受客户端提交，不得回退管理角色 |
| 部门和岗位 | 不适用 | 无 | 服务端固定为无部门、无岗位语义 | 不创建虚拟部门，不参与管理端组织树 |

### 7.2 当前访问规则

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 查询注册是否开放 | 否 | 仅返回注册页面所需的最小配置 | 返回关闭状态，不泄露内部配置 |
| 获取图形验证码 | 否 | 符合验证码接口频率要求 | 超限时暂时拒绝 |
| 提交注册 | 否 | 注册开启、租户有效、角色有效、输入和验证码合法 | 返回明确业务失败且不创建用户 |
| 注册后登录 | 否 | 用户已启用，租户、账号和密码匹配 | 失败时不签发令牌 |
| 访问普通用户页面 | 是 | 具有对应菜单和接口权限 | 页面不展示入口，服务端拒绝越权请求 |
| 访问管理功能 | 是 | 必须具有管理角色或明确管理权限 | 普通用户统一拒绝 |

### 7.3 权限影响

- 注册接口是匿名公开入口，不通过登录角色授权，必须通过注册开关、验证码、租户校验、输入规则和频率限制保护。
- 注册用户默认角色为目标租户普通用户角色，具体稳定标识和配置方式在详细设计中确定。
- 普通用户角色不得包含用户、角色、租户、菜单、部门、岗位等管理权限。
- Saber 隐藏菜单和按钮不是唯一保护手段，服务端仍必须执行现有认证、角色和接口权限校验。
- 无部门、无岗位不代表全租户数据权限；具体业务接口仍需按用户、角色、租户和资源归属执行访问控制。

## 8. 页面与交互要求

### 8.1 页面与操作

| 页面/入口 | 用户目标 | 主要操作 | 可见角色 | 原型链接 |
| --- | --- | --- | --- | --- |
| Saber 登录页 | 在登录和注册之间切换 | 选择登录或注册 | 未登录用户 | 无 |
| Saber 注册表单 | 创建普通用户账号 | 填写租户、账号、昵称、密码、确认密码和验证码并提交 | 未登录用户且注册已开启 | 无 |
| Saber 登录表单 | 使用注册账号登录 | 填写租户、账号和密码 | 未登录用户 | 复用现有页面 |

注册表单交互要求：

1. 租户编号标记为选填，并明确未填写时使用默认租户 `000000`。
2. 昵称标记为选填，未填写时使用账号作为初始昵称。
3. 密码和确认密码使用密码输入控件，不以明文持续展示。
4. 图形验证码支持刷新；提交失败后已经消耗或无效的验证码必须刷新。
5. 提交期间禁用重复提交操作。
6. 注册成功后显示明确成功反馈并切换回登录表单。

### 8.2 页面状态

| 状态 | 展示与行为 |
| --- | --- |
| 注册关闭 | 不提供可提交的注册入口，登录功能正常可用 |
| 表单初始状态 | 展示账号密码注册表单和图形验证码，租户及昵称为选填 |
| 验证码加载中 | 保留稳定布局，验证码区域显示加载状态且不可提交 |
| 提交中 | 显示提交状态并禁止重复提交、切换或再次点击 |
| 字段校验失败 | 在对应字段附近展示可修正的错误信息，不发送无效请求 |
| 请求失败 | 保留非敏感输入，清空密码和验证码，提供重新提交入口 |
| 频率受限 | 提示稍后重试，不反复自动请求 |
| 提交成功 | 显示注册成功信息，返回登录表单并清除密码和验证码 |

## 9. 质量要求与影响

### 9.1 非功能要求

| 类别 | 要求 | 验证标准 |
| --- | --- | --- |
| 安全 | 公开注册必须受开关、验证码、租户校验、角色边界和频率限制保护 | 关闭、伪造租户/角色、验证码失败和超限场景均被拒绝 |
| 敏感信息 | 密码、确认密码、验证码、令牌和密钥不得出现在响应或日志中 | 检查注册成功与失败响应、应用日志和网关日志 |
| 并发 | 同一租户同一账号的并发注册最多成功一次 | 并发执行后数据库只有一个对应账号 |
| 一致性 | 注册失败不得产生部分用户、错误角色关联或虚拟部门 | 依赖失败和数据库异常后检查无新增残留 |
| 兼容性 | 注册功能关闭时现有登录、第三方登录和管理端用户维护不受影响 | 对现有认证和用户管理流程执行回归检查 |
| 可用性 | 注册失败信息应可理解和可恢复，不暴露内部异常或账号密码信息 | 主要失败场景返回稳定业务语义并可重新操作 |
